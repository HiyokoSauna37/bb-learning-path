Node.js / Express Security Audit

Express アプリケーションの典型的脆弱性パターン。Middleware ordering, Prototype Pollution, MongoDB Injection から Template Injection まで。

Theory Hands-on Case Study

Express Middleware Ordering Issues

Express は middleware を登録順に実行する。順序ミスは auth bypass に直結する。

// 危険: route が auth middleware より先に登録されている
app.use('/api/public', publicRoutes);
app.use('/api', authMiddleware);  // /api/public は素通り
app.use('/api/admin', adminRoutes);

// 安全: auth を先に適用
app.use('/api', authMiddleware);
app.use('/api/public', skipAuth, publicRoutes);
app.use('/api/admin', adminRoutes);

Route Parameter Pollution

// Express は同名パラメータを配列にする場合がある
// GET /api/users?role=admin&role=user
// req.query.role = ['admin', 'user']

// 危険: 文字列比較のつもりが配列で通過
if (req.query.role !== 'admin') {
    // ['admin', 'user'] !== 'admin' は true... bypass!
}

Prototype Pollution

JavaScript の prototype chain を汚染し、全 object に任意プロパティを注入する攻撃。

危険パターン

// Deep merge without prototype check
function merge(target, source) {
    for (let key in source) {
        if (typeof source[key] === 'object') {
            target[key] = merge(target[key] || {}, source[key]);
        } else {
            target[key] = source[key];
        }
    }
    return target;
}

// Attack payload:
// {"__proto__": {"isAdmin": true}}
// 全 object に isAdmin = true が注入される

grep パターン

rg -n "Object\.assign\(|\.merge\(|deepMerge\(|extend\(" --type js
rg -n "lodash\.merge|_.merge|deepmerge" --type js
rg -n "\[key\]\s*=" --type js  # dynamic property assignment

対策の確認ポイント

  • __proto__, constructor, prototype キーのブロック有無
  • Object.create(null) の使用有無
  • hasOwnProperty チェックの有無

require() Injection / eval / Function

// Command Injection via child_process
const { exec } = require('child_process');
exec(`git clone ${req.body.url}`);  // Injection!

// eval with user input
const result = eval(req.body.expression);

// Function constructor (hidden eval)
const fn = new Function('return ' + req.body.code);

// require() injection (rare but critical)
const module = require(req.body.plugin);  // RCE

grep パターン

rg -n "exec\(|execSync\(|spawn\(" --type js
rg -n "eval\(|new Function\(" --type js
rg -n "require\(.*req\." --type js
rg -n "vm\.(runIn|createContext)" --type js

Template Injection (EJS / Pug)

// EJS: Server-Side Template Injection
// 危険: ユーザ入力を template 文字列に直接埋め込み
app.get('/preview', (req, res) => {
    const template = `<h1>Hello ${req.query.name}</h1>`;
    res.render(template);  // SSTI if render parses EJS tags
});

// EJS RCE payload:
// <%= global.process.mainModule.require('child_process').execSync('id') %>

// Pug SSTI:
// #{7*7} → 49 (expression evaluation)
EJS の settings['view options'] 汚染

Prototype Pollution と EJS を組み合わせると RCE に escalate できる。settings['view options'] 経由で outputFunctionName を汚染し、任意コード実行が可能。

MongoDB Injection

NoSQL でも Injection は発生する。$gt, $ne, $regex operator を注入する。

// 危険: req.body を直接 query に使用
const user = await User.findOne({
    username: req.body.username,
    password: req.body.password
});

// Attack payload:
// {"username": "admin", "password": {"$ne": ""}}
// → password が空でない限り全て match → auth bypass

// $regex による情報抽出:
// {"password": {"$regex": "^a"}}  → starts with 'a'?

grep パターン

rg -n "findOne\(.*req\.|find\(.*req\.|updateOne\(.*req\." --type js
rg -n "\\\$where|\\\$regex|\\\$gt|\\\$ne|\\\$exists" --type js
rg -n "mongoose.*\{.*req\.(body|query|params)" --type js

Real Cases

Case 1: Flowise WHITELIST_URLS Bypass

問題: Express middleware が WHITELIST_URLS 配列で認証をスキップする route を管理。

Vulnerability: startsWith() で prefix match していたため、/api/v1/public のつもりが /api/v1/public/../admin で bypass 可能。さらに 6+ sibling endpoint が同パターンで無認証アクセス可能。

// Flowise の問題パターン
const WHITELIST_URLS = ['/api/v1/public', '/api/v1/verify'];
if (WHITELIST_URLS.some(url => req.path.startsWith(url))) {
    return next(); // auth skip
}

Case 2: AnythingLLM Middleware Missing

問題: validWorkspaceSlug middleware が一部 route にのみ追加され、他 route は無防備。

発見方法: git diff で middleware 追加 commit を特定 → 同 router の他 route を grep → 2 endpoint に middleware 欠落。

Key Takeaways

  • Middleware ordering は Express 最大の罠 — 登録順 = 実行順を常に意識
  • Prototype Pollution は単体で Low でも EJS/Handlebars と組むと RCE に化ける
  • MongoDB Injection は JSON body で operator を注入 — $ne, $gt, $regex
  • WHITELIST pattern は必ず sibling を探す — 1箇所見つけたら 6+ 見つかることが多い
  • huntr OSS 対象の多くが Express ベース — このモジュールの知識だけで多くの finding に到達可能
