Tools Setup & Workflow

BB ハンティングに必要なツール群のセットアップと、効率的な調査ワークフローを構築する。

Hands-on Practice

Burp Suite

BB ハンターの標準ツール。HTTP/HTTPS 通信の intercept, 改ざん, 再送, 自動スキャンを行う。 Community Edition (無料) でも Proxy, Repeater, Intruder (速度制限あり) が使える。

Core Features

機能用途BB での使い方
Proxy通信の傍受と改ざん認証リクエストの構造理解、パラメータ特定
Repeaterリクエストの手動編集と再送パラメータ操作、PoC 構築
Intruder自動化された攻撃 (brute force, fuzzing)パラメータ列挙、IDOR のID走査
Scanner (Pro)自動脆弱性スキャンXSS, SQLi の初期検出
Decoderエンコード/デコードBase64, URL, HTML entity の変換
Comparerレスポンス差分比較認証あり/なしの差分、role 別の差分

Setup 手順

# 1. Burp Suite ダウンロード
# https://portswigger.net/burp/releases

# 2. CA 証明書のインストール
# Burp 起動 → Proxy → Options → Import/Export CA Certificate
# ブラウザに CA をインストール (Firefox: Settings → Certificates → Import)

# 3. ブラウザのプロキシ設定
# FoxyProxy (Firefox/Chrome extension) で 127.0.0.1:8080 を設定
# またはシステムプロキシを設定

# 4. HTTPS intercept の確認
# https://burpsuite にアクセスして "Burp Suite Community Edition" が表示されれば成功

BB視点: Burp Community vs Pro

Community Edition の Intruder は速度制限 (throttled) がある。 BB を本格的にやるなら Pro ($449/year) は投資回収しやすい。 ただし Community + 手動 + Python scripting でも十分に成果は出せる。 最初は Community で始めて、最初の報酬で Pro に移行するのが現実的。

Caido

Burp Suite のモダンな代替ツール。Rust 製で高速、UI が直感的。 Free tier でも Proxy, Replay (Repeater相当), Automate (Intruder相当) が使える。

Browser DevTools

Proxy ツールなしでも多くの情報が得られる。特に初期調査で重要。

Network タブ

  • XHR/Fetch フィルタで API コールを特定
  • Response headers で CORS, CSP, Cookie 属性を確認
  • Copy as cURL でリクエストを再現
  • Initiator でどの JS がリクエストを発行したか追跡

Application タブ

  • Cookies: 属性 (HttpOnly, Secure, SameSite) を一覧
  • Local Storage / Session Storage: JWT やトークンの保存確認
  • Service Workers: cache 内容、offline 時の挙動

Console タブ

// Cookie の一覧 (HttpOnly 以外)
document.cookie

// 現在のページで使われている全イベントリスナー
getEventListeners(document)

// fetch で API テスト
fetch('/api/admin/users', {credentials: 'include'})
  .then(r => r.json()).then(console.log)

// postMessage の監視 (XSS via postMessage の調査)
window.addEventListener('message', e => console.log(e.origin, e.data))

Command-Line Tools

curl

# 基本的な GET
curl -v https://api.target.com/users/me

# POST with JSON
curl -X POST https://api.target.com/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","password":"pass"}'

# Cookie 付きリクエスト
curl -b "session=abc123" https://api.target.com/admin

# 出力を jq でパース
curl -s https://api.target.com/users | jq '.[] | {id, role}'

# Follow redirects + show headers
curl -L -D - https://target.com/oauth/callback?code=xxx

httpie (curl の代替)

# より読みやすい出力
http GET https://api.target.com/users Authorization:"Bearer token123"

# POST (JSON が自動)
http POST https://api.target.com/login email=test@test.com password=pass

# Form data
http --form POST https://target.com/upload file@exploit.html

Python requests

import requests

# Session を使って Cookie を自動管理
s = requests.Session()

# Login
s.post('https://target.com/login', json={
    'email': 'test@test.com',
    'password': 'password'
})

# Authenticated request (Cookie は自動送信)
r = s.get('https://target.com/api/admin/users')
print(r.status_code, r.json())

# IDOR テスト
for user_id in range(1, 100):
    r = s.get(f'https://target.com/api/users/{user_id}')
    if r.status_code == 200:
        print(f"Accessible: user {user_id} - {r.json()}")

Docker for Local Testing

対象アプリケーション (OSS) をローカルで動かして、安全にテストする環境を構築する。 BB (特に huntr.com) では PoC 環境の構築が必須。 

# 典型的な PoC 環境のセットアップ
# 例: Node.js アプリ
git clone https://github.com/target/vulnerable-app.git
cd vulnerable-app
docker-compose up -d

# 例: Rails アプリ
docker-compose run web rails db:setup
docker-compose up

# PostgreSQL + Redis + App の典型構成
# docker-compose.yml
version: '3'
services:
  db:
    image: postgres:15
    environment:
      POSTGRES_PASSWORD: password
  redis:
    image: redis:7
  app:
    build: .
    ports:
      - "3000:3000"
    depends_on:
      - db
      - redis
BB視点: PoC 環境の重要性

huntr.com (OSS BB) では再現環境の構築が report quality に直結する。 Docker でワンコマンドで再現できる PoC は triage 速度を上げ、報酬確定が早まる。 また、production に影響を与えずに destructive なテスト (SQLi, file write 等) が可能。

Workflow: Intercept → Analyze → Modify → Replay

Burp Suite のリクエストフロー

flowchart LR B[Browser] -->|"1. Request送信"| P["Burp Proxy
Intercept"] P -->|"2. 確認/改ざん"| S[Server] S -->|"3. Response"| P P -->|"4. 確認"| B P -->|"コピー"| R["Repeater
繰り返しテスト"] R -->|"改変して再送"| S P -->|"コピー"| I["Intruder
自動化テスト"] I -->|"大量パターン送信"| S

1. Intercept (通信の傍受)

  • Burp/Caido の Proxy で通信を記録
  • 通常のユーザー操作を一通り行い、API の全体像を把握
  • 認証フロー、権限切り替え、ファイルアップロード等を重点的に記録

2. Analyze (分析)

  • API endpoint の一覧を作成 (Site Map)
  • 認証トークンの構造を解析 (JWT? Session Cookie? API Key?)
  • パラメータの命名規則からパターンを推測 (user_id, account_id → IDOR)
  • レスポンスヘッダーから技術スタックを特定 (X-Powered-By, Server)

3. Modify (改ざん)

  • パラメータ値の変更 (IDOR: 自分のID → 他人のID)
  • HTTP Method の変更 (GET → PUT/DELETE)
  • 認証ヘッダーの削除/低権限への差し替え
  • Content-Type の変更 (parser differential)

4. Replay (再送と観察)

  • Repeater で改ざんリクエストを送信
  • レスポンスの差分を Comparer で比較
  • 成功したら PoC スクリプトに変換 (Python/curl)
  • 再現性を確認して report 作成

Key Takeaways

  • Burp Suite は BB の必須ツール。Authorize extension で IDOR/BAC を半自動化。
  • Caido はモダンで高速。Burp と併用して使い分けるのが効率的。
  • DevTools だけでも初期調査は十分可能。Network + Application タブを活用。
  • Python requests で PoC を再現可能な形にする。report の質が上がる。
  • Docker は OSS BB で必須。ワンコマンド再現環境を心がける。
  • Workflow: Intercept → Analyze → Modify → Replay のサイクルを高速で回す。
