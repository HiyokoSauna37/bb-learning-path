Platform Operations

各 BB platform の特性、運用ルール、選択基準を理解する。 Platform の選択は戦略の根幹。

Theory

主要 Platform

HackerOne

世界最大の BB platform | 米国拠点 | W-8BEN 必要

Signal / Reputation System

  • Signal: レポート品質の指標。Resolved=+, N/A=-5, Spam=-10, Dup=除外
  • Reputation: 累積ポイント。Private invite の閾値に影響
  • Signal > 1.0 を維持することが最優先

Program Types

  • Managed: HackerOne triage team が一次対応。Response SLA あり。高品質だが bounty も高い
  • Self-serve: 企業が直接 triage。Response time は企業次第

Bounty Table

Program ごとに severity-based table。Critical: $5K-$50K+, High: $2K-$15K, Medium: $500-$5K, Low: $100-$1K（program による）

Private Invites

Signal + activity + past performance に基づいて invite される。招待制 program は competition が低い = dup 率が低い。

Intigriti

ヨーロッパ中心 | ベルギー拠点 | GDPR 文化

特徴

  • Triage 品質が高い（専門チームが迅速に判定）
  • European 企業が多い（Telco, Banking, eCommerce）
  • Severity-based payout

AI Disclosure Requirement (2026-03)

  • CoC 更新で AI 使用の when/how disclosure が必須
  • 違反 = report close + platform 除外の可能性
  • 「AI was used for: code analysis, PoC validation」のように具体的に記載
  • Submission limits も同時導入 — 品質重視の方針

IssueHunt

#1 Japan BB Platform | 日本語対応 | 16 paid programs

主要プログラム

  • SORACOM, ABEMA, bitFlyer, LINE WORKS, Tapple 等
  • 日本企業が多い = 日本語でのコミュニケーション可能な場合あり
  • Competition が HackerOne より低い

注意点

  • Program 数が限定的（16 paid public programs）
  • 日本の法律が適用される（不正アクセス禁止法に注意）
  • Program list API で最新状況を確認可能

huntr

OSS 特化 | AI/ML repos が豊富 | Source code audit

特徴

  • OSS リポジトリが対象 — ソースコードが完全に読める
  • AI/ML フレームワーク (LangChain, LiteLLM, etc.) が多い
  • Disclose form: /bounties/disclose（旧 /repos/{owner}/{repo}/bounties/disclose は 404）
  • Report format: Description + Impact + Occurrences を 1 ファイルで

Bounty

$50-$3,000 (プロジェクトと severity により異なる。最新は huntr.com で確認)。金額は低いが Signal 蓄積に有効。

Bugcrowd

米国拠点 | VRT (Vulnerability Rating Taxonomy)

特徴

  • VRT で severity を標準化（program 独自の判定基準を上書き）
  • Severity-based payout（P1-P4）
  • Researcher-friendly な reputation system

GHSA (GitHub Security Advisory)

GitHub native | Bounty なし | Portfolio 構築用

特徴

  • Private vulnerability reporting で maintainer に直接報告
  • CVE 番号の自動採番が可能
  • Bounty はないが、公開された advisory は portfolio として有効
  • OSS への貢献実績として GitHub profile に表示される

初心者向け戦略

  1. huntr (OSS) でソースコード監査のスキルを磨く
  2. Low-competition program で Signal を蓄積
  3. Signal > 1.0 になったら HackerOne の public program へ
  4. Private invite を得たら competition が低い program で bounty を狙う

Account Setup Checklist

  • HackerOne: Profile 充実 (bio, skills, certifications)、W-8BEN 提出、2FA 有効化
  • Intigriti: KYC verification (EU 要件)、AI disclosure テンプレ準備
  • IssueHunt: 日本語 profile、銀行口座情報
  • huntr: GitHub 連携、notification 設定
  • 共通: Dedicated email (BB 専用)、VPN 設定確認、Burp Pro ライセンス

Response Time の読み方

Program の response time は BB 体験に直結する。確認すべき指標:

  • Time to First Response: 最初の返信までの時間。7日以内が理想
  • Time to Triage: Triaged ステータスまでの時間。Managed program は通常 1-3日
  • Time to Bounty: Bounty 支払いまでの時間。Program による差が大きい (1週間〜6ヶ月)
  • Time to Resolution: Fix + Close までの時間。内部の dev cycle に依存

HackerOne では program page に median response time が表示される。これを必ず確認してから submit。
