Python (Flask/Django/FastAPI) Audit

Python Web フレームワーク固有の脆弱性パターン。SSTI, Pickle Deserialization, ORM Bypass, subprocess injection を中心に。

Theory Hands-on

Jinja2 Server-Side Template Injection (SSTI)

Flask のデフォルトテンプレートエンジン Jinja2 で、ユーザ入力がテンプレートとして解釈される場合に発生。

# 危険: render_template_string にユーザ入力
from flask import render_template_string, request

@app.route('/greet')
def greet():
    name = request.args.get('name', 'World')
    return render_template_string(f'<h1>Hello {name}</h1>')

# Attack: ?name={{7*7}} → "Hello 49"
# RCE: ?name={{config.__class__.__init__.__globals__['os'].popen('id').read()}}

SSTI Detection (grep)

rg -n "render_template_string\(" --type py
rg -n "Template\(.*request\." --type py
rg -n "Environment\(.*\.from_string\(" --type py
rg -n "format\(.*request\." --type py  # f-string injection variant

安全/危険の境界

パターン安全性理由
render_template('tpl.html', name=input)安全template は固定ファイル、input は変数として渡される
render_template_string(input)危険input 自体が template として解釈される
render_template_string(f"...{input}...")危険f-string 展開後に template parse される

Django ORM Bypass

Django ORM は基本的に安全だが、extra(), raw(), RawSQL() は SQL Injection のリスクがある。

# 危険: raw() with string formatting
User.objects.raw(f"SELECT * FROM users WHERE name = '{name}'")

# 危険: extra() with user input
queryset.extra(where=[f"name = '{request.GET['name']}'"])

# 危険: annotate with RawSQL
from django.db.models.expressions import RawSQL
queryset.annotate(val=RawSQL(f"SELECT {user_input} FROM ..."))

# 安全: parameterized
User.objects.raw("SELECT * FROM users WHERE name = %s", [name])

grep パターン

rg -n "\.raw\(|\.extra\(|RawSQL\(" --type py
rg -n "cursor\.execute\(.*format\(|cursor\.execute\(.*%" --type py
rg -n "connection\.cursor\(\)" --type py

Pickle / YAML Deserialization

Pickle (RCE 直結)

import pickle

# 危険: untrusted data を pickle.loads
data = request.get_data()
obj = pickle.loads(data)  # RCE!

# Attack: __reduce__ method で任意コマンド実行
import os
class Exploit:
    def __reduce__(self):
        return (os.system, ('id',))

YAML unsafe_load

import yaml

# 危険: yaml.load without Loader specification (PyYAML < 5.1 (5.1以降は Loader 引数必須、6.0以降はエラー))
config = yaml.load(request.data)

# 危険: yaml.unsafe_load (明示的に unsafe)
config = yaml.unsafe_load(user_input)

# 安全: SafeLoader
config = yaml.safe_load(user_input)
config = yaml.load(user_input, Loader=yaml.SafeLoader)

grep パターン

rg -n "pickle\.(loads|load)\(" --type py
rg -n "yaml\.(load|unsafe_load)\(" --type py
rg -n "yaml\.load\(" --type py  # Loader 指定の有無を確認
rg -n "shelve\.open\(|marshal\.loads\(" --type py

subprocess / os Injection

# 危険: shell=True with user input
import subprocess
subprocess.run(f"git clone {url}", shell=True)

# 危険: os.system
import os
os.system(f"ping {request.args['host']}")

# 安全: shell=False (default) + list arguments
subprocess.run(["git", "clone", url], shell=False)

# 注意: shlex.quote は Linux 限定。Windows では別の対策が必要

grep パターン

rg -n "subprocess\.(run|call|Popen|check_output)\(.*shell=True" --type py
rg -n "os\.(system|popen|exec)\(" --type py
rg -n "commands\.getoutput\(" --type py

os.path.join Bypass (Path Traversal)

import os

# 危険: absolute path で join をリセット
base = "/app/uploads"
filename = request.args['file']
path = os.path.join(base, filename)

# Attack: filename = "/etc/passwd"
# os.path.join("/app/uploads", "/etc/passwd") → "/etc/passwd"
# 先頭 / で base が無視される!

# 対策: os.path.basename() で先にファイル名のみ抽出
safe_name = os.path.basename(filename)
path = os.path.join(base, safe_name)
os.path.join の罠

os.path.join("base", "/absolute") は "/absolute" を返す。.. だけでなく absolute path による bypass にも注意。

Framework-Specific Issues

Flask

  • Debug Mode: app.run(debug=True) — Werkzeug debugger で RCE (PIN bypass 可能)
  • SECRET_KEY: ハードコードされた weak key → session cookie forgery
  • send_file / send_from_directory: path traversal の sink

Django

  • SECRET_KEY exposure: settings.py にハードコード → session/CSRF token forgery
  • DEBUG = True in production: stack trace でソースコードが漏洩
  • ALLOWED_HOSTS = ['*']: Host header injection
  • @csrf_exempt: 不要な CSRF 保護除外

FastAPI

  • Dependency Injection: Depends() の auth check 漏れ (Express middleware と同じ問題)
  • Pydantic bypass: model.dict() で extra fields が通過する設定
  • /docs, /redoc: production で OpenAPI docs が公開されている
# FastAPI auth 漏れパターン
from fastapi import Depends

async def get_current_user(token: str = Header()):
    ...

# 危険: dependency 付け忘れ
@app.get("/admin/users")
async def list_users():  # get_current_user が Depends されていない!
    return db.get_all_users()

SQLAlchemy Raw Queries

from sqlalchemy import text

# 危険: f-string で query 構築
result = db.execute(text(f"SELECT * FROM users WHERE name = '{name}'"))

# 安全: parameterized
result = db.execute(text("SELECT * FROM users WHERE name = :name"), {"name": name})

Key Takeaways

  • SSTI: render_template_string + user input = RCE。render_template (固定ファイル) なら安全
  • Pickle/YAML: untrusted data の deserialization は即 RCE。yaml.safe_load を必ず確認
  • os.path.join: absolute path 引数で base directory が無視される罠
  • Django ORM: raw(), extra(), RawSQL() のみ SQL injection risk
  • subprocess shell=True + user input = Command Injection
  • Framework config: SECRET_KEY, DEBUG, ALLOWED_HOSTS は即チェックする低コスト監査項目
