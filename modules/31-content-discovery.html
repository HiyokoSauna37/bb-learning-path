Content & Endpoint Discovery

隠されたディレクトリ、忘れ去られたファイル、ドキュメント化されていない endpoint を見つけ出す。

Theory Practice

Content Discovery とは

Subdomain enumeration でホストを見つけた後、各ホスト上に存在するパス、ファイル、 API endpoint を網羅的に洗い出すフェーズ。公開されていないが存在する admin panel、backup file、設定ファイルなどが見つかることが多い。

Directory Brute Force

ffuf (Fuzz Faster U Fool)

Go 製の高速 fuzzer。柔軟なフィルタリングが強み。

# 基本的なディレクトリ探索
ffuf -u https://target.com/FUZZ -w wordlist.txt

# ステータスコードでフィルタ
ffuf -u https://target.com/FUZZ -w wordlist.txt \
  -mc 200,301,302,403

# サイズでフィルタ (WAF の共通レスポンスを除外)
ffuf -u https://target.com/FUZZ -w wordlist.txt -fs 1234

# 拡張子付き
ffuf -u https://target.com/FUZZ -w wordlist.txt \
  -e .php,.asp,.aspx,.jsp,.bak,.old,.txt,.conf

# ヘッダー付き (認証後のパス探索)
ffuf -u https://target.com/FUZZ -w wordlist.txt \
  -H "Cookie: session=abc123"

feroxbuster

Rust 製。再帰的探索がデフォルトで、深い階層のパスを自動で発見する。

# 再帰的探索 (depth 4)
feroxbuster -u https://target.com -w wordlist.txt -d 4

# 拡張子 + ステータスフィルタ
feroxbuster -u https://target.com -w wordlist.txt \
  -x php,asp,bak -C 404,403

dirsearch

Python 製。設定済みの拡張子リストが豊富で、初心者に使いやすい。

dirsearch -u https://target.com -e php,asp,aspx,jsp,bak
Wordlist の選択が命
  • SecLists/Discovery/Web-Content/ — 定番
  • raft-large-*.txt — 広範囲カバー
  • common.txt — 高速スキャン向け
  • 技術スタック固有 — WordPress なら wp-specific list
  • カスタムリストの構築: 対象のドキュメント、JS ファイルから抽出した path を追加

Historical Endpoint Discovery

Wayback Machine (web.archive.org)

過去に存在したが現在は削除された endpoint を発見できる。

# waybackurls - CLI で過去URL取得
echo target.com | waybackurls > wayback_urls.txt

# gau (Get All URLs) - Wayback + OTX + Common Crawl
echo target.com | gau --threads 5 > all_urls.txt

# パラメータ付きURLだけ抽出
cat all_urls.txt | grep "=" | sort -u > params.txt

# 興味深いパターンをフィルタ
cat all_urls.txt | grep -E "(admin|api|internal|debug|test)" > interesting.txt
BB視点: 削除された endpoint の価値

Wayback で見つかった endpoint が現在も 200 を返す場合、開発者は 「リンクを消しただけで endpoint は残っている」状態。 認証チェックが甘いことが多い。

GitHub Dorking

開発者がうっかりコミットした secrets や内部 URL を GitHub 検索で発見する。 

# GitHub 検索クエリ例
org:targetcompany password
org:targetcompany api_key
org:targetcompany token
org:targetcompany secret
org:targetcompany internal
"target.com" password
"target.com" apikey

# 有用なファイル検索
org:targetcompany filename:.env
org:targetcompany filename:config
org:targetcompany filename:credentials
org:targetcompany extension:pem
org:targetcompany extension:key

自動化ツール

  • trufflehog — Git history から secret をスキャン
  • gitleaks — repo 全体の secret 検出
  • gitdorker — GitHub dorking の自動化

Google Dorking

Google の検索演算子でインデックスされた機密情報を探す。

# 基本パターン
site:target.com filetype:pdf
site:target.com filetype:xlsx
site:target.com inurl:admin
site:target.com inurl:login
site:target.com intitle:"index of"
site:target.com ext:sql | ext:bak | ext:old
site:target.com inurl:api

# エラーメッセージから情報取得
site:target.com "internal server error"
site:target.com "stack trace"
site:target.com "sql syntax"

# 設定ファイル露出
site:target.com ext:xml | ext:conf | ext:cnf | ext:ini

Known Paths の確認

robots.txt

クローラーに「来るな」と伝えるファイルだが、逆に機密パスが列挙されていることがある。

curl https://target.com/robots.txt
# Disallow: /admin/
# Disallow: /internal/
# Disallow: /api/v1/debug/

sitemap.xml

curl https://target.com/sitemap.xml
curl https://target.com/sitemap_index.xml

.well-known/ パス

# セキュリティ関連
curl https://target.com/.well-known/security.txt
curl https://target.com/.well-known/openid-configuration

# Apple/Android 関連
curl https://target.com/.well-known/apple-app-site-association
curl https://target.com/.well-known/assetlinks.json

その他の定番パス

/.git/config          # Git repo 露出
/.env                 # 環境変数ファイル
/server-status        # Apache status page
/elmah.axd            # .NET error log
/phpinfo.php          # PHP info exposure
/wp-json/wp/v2/users  # WordPress user enum
/actuator/env         # Spring Boot actuator

Key Takeaways

  • Wordlist = 武器の質 — 汎用リストだけでなく、対象固有のカスタムリストを構築する
  • 過去データは宝の山 — Wayback, Google cache から削除済みだが生きている endpoint を発見
  • GitHub は secrets の宝庫 — org 検索、コミット履歴検索で credentials を発見
  • robots.txt は隠す意図の露出 — Disallow されたパスは優先的に調査する
  • フィルタリングが鍵 — WAF の共通レスポンスを除外して真のヒットだけ残す
