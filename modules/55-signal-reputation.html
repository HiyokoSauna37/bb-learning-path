Signal & Reputation Management

HackerOne Signal は BB キャリアの生命線。一度下げると回復に時間がかかる。 Quality-first approach で長期的に Signal を積み上げる戦略。

Theory

HackerOne Signal 計算

Signal は過去のレポート結果から算出される品質スコア。Default = 0.0、Maximum = 7.0。

Report ResultSignal Impact備考
Resolved (Bounty paid)+7最大の positive signal
Resolved (No bounty)+7VDP でも同じ
Triaged+5Bounty 前でも positive
Informative0Neutral (害はない)
DuplicateExcludedSignal 計算から除外 (プラスもマイナスもなし)。Reputation に early +2 / late -5 の別計算あり
Not Applicable (N/A)-5大きなダメージ
Spam-10致命的ダメージ

Key Insight

  • Dup は Signal に影響しない。恐れるべきは N/A と Spam
  • Signal = (sum of impacts) / (number of counted reports)。Dup は分母にも分子にも入らない。Note: HackerOne の実際の Signal 計算は加重移動平均で、この単純平均は概念理解用の近似。正確な計算式は非公開。
  • 1件の N/A を打ち消すには Resolved が 1件必要
  • 1件の Spam を打ち消すには Resolved が 2件弱必要

Reputation Building 戦略

Phase 1: Signal > 1.0 を確保

  • 最初の数件は確実に Triaged/Resolved になるものだけ submit
  • Low-competition program (新しい program, response time が短い)
  • huntr/GHSA で verified な finding を蓄積（Signal には直接影響しないが実力を証明）
  • 「怪しいけど確信がない」ものは submit しない

Phase 2: Private Invite を獲得

  • Signal > 1.0 + consistent activity で invite が来始める
  • Private program は参加者が限定されるため dup 率が低い
  • Bounty range も public program より高い傾向
  • 一度 invite されたら response time を意識（SLA 違反で invite revoke あり）

Phase 3: 安定運用

  • Quality-first を維持。1件の Critical > 10件の Informative
  • Signal を下げないために N/A リスクのある報告は見送る
  • 新しい program が launch されたら早期参入（competition が低い）

Signal ダメージの回避

N/A になりやすいパターン

  • Scope 外のアセットへの報告
  • 「脆弱性ではないが informational」な報告（best practice 違反等）
  • 既に vendor が「Won't Fix」と決めている known issue
  • Design intent として意図された behavior
  • Impact が実証されていない speculative report

Submit して安全な条件

  • PoC で impact を完全に実証済み
  • Scope 内のアセットであることを確認済み
  • Dup check 3軸を通過
  • bb-aislop-gate scan が PASS
  • 4-axis pre-submit audit を通過

Quality over Quantity

BB 初心者がやりがちな mistake: 「数を打てば当たる」戦略。実際には逆効果。

戦略結果Signal 影響
10件 submit (7 N/A, 2 Dup, 1 Resolved)$500 bountySignal = (7 + 7*(-5)) / 8 = -3.5
2件 submit (1 Resolved, 1 Dup)$500 bountySignal = 7/1 = 7.0

同じ bounty 額でも Signal が天と地ほど違う。Signal が低いと private invite が来なくなり、long-term revenue が激減する。

Program 選択 for Signal Building

  • Response time が短い program — Triaged が早く Signal に反映
  • Scope が明確な program — N/A risk が低い
  • 新 launch program — Competition が低く、easy win が残っている
  • VDP (Vulnerability Disclosure Program) — Bounty はないが Resolved = +7 signal

実践 Tips

  • Submit 前に「これが N/A で返ってきたら納得するか？」と自問
  • 確信が 80% 未満なら submit しない
  • Triage team のコメントを注意深く読む — 次回の判断基準になる
  • Resolved 後に disclosure request を出す — 公開レポートは portfolio になる
  • 他の hunter の disclosed report を読んで基準を学ぶ

Signal Recovery Strategy

Signal が下がってしまった場合の回復方法:

短期回復 (1-2週間)

  • VDP (Vulnerability Disclosure Program) で確実な finding を submit → Resolved = +7
  • Response time が短い program を選ぶ（Triaged = +5 が早く反映）
  • huntr で verified な finding → Signal 対象外だが実力証明に使える

中期安定化 (1-3ヶ月)

  • Submit 頻度を下げて quality を上げる
  • bb-submit-gate の 8 gates を厳格に適用（1つでも FAIL なら submit しない）
  • N/A risk のある報告は完全に見送る
  • Signal > 1.0 に回復するまで conservative mode を維持
