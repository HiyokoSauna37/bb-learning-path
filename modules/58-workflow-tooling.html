Workflow & Tooling (mei-bb)

mei-bb の 3-Phase workflow と bb-toolkit (40+ commands) の全体像。 Phase ごとに使うツールを整理し、効率的な BB session を実現する。

Hands-on Theory

3-Phase Workflow

Phase 0: Triage Phase 1: Hypothesis & PoC Phase 2: Submit +-----------------+ +------------------------+ +------------------+ | program-discover| | bb-engage init | | bb-mode submit | | target-precheck | --> | middleware-audit | --> | submit-gate (8) | | ghsa list | | whitelist-audit | | cvss compute | | submission-status| | mschema-check | | aislop-gate scan | +-----------------+ | rng-fuzz | +------------------+ +------------------------+

Phase 0: Triage

Target 選定と事前調査。Program の viable 判定、既知 dup zone の確認、先行 submission の status check。

目的

  • 有望な target を選定する
  • 既知の dup zone を避ける
  • Active な submission が重複しないか確認
  • Program の scope / rules を把握する
bb-program-discover

Paid platform の program 一覧取得、response time / bounty range でソート

bb-target-precheck

Platform 登録確認、scope size、competition level の overview

bb-program-precheck

Opsec/automation policy、scope size を 1-view 判定。NOT_VIABLE なら即 pivot

bb-submission-status

Active な提出済み report の status 確認（同日重複作業防止）

bb-ghsa list

対象リポジトリの全 GHSA/CVE を列挙。Dup check の canonical 経路

Phase 1: Hypothesis & PoC

仮説を立て、実機で検証し、PoC を作成する。ここが BB の core work。

目的

  • 脆弱性仮説を構築する
  • 実機 (runtime) で再現を確認する
  • Minimal PoC を作成する
  • Impact を実証する
bb-engage init

Session 開始。Target lock-in、iteration budget 設定

bb-middleware-audit

Express/Koa/connect-style middleware の auth bypass / incomplete-fix 検出 (Go)

bb-whitelist-audit

WHITELIST_URLS auth-bypass anti-pattern 検出。Sibling endpoint の列挙

bb-mschema-check

Mongoose schema validation (String vs ObjectId silent miss 検出)

bb-rng-fuzz

Token predictability の multi-shape audit (4+ realistic input)

Phase 2: Submit

Submit 前の最終ゲートチェック。品質保証のための 8 gates を全て PASS して初めて submit。

目的

  • AI Slop / false positive を排除する
  • Severity を正確に計算する
  • Report format を platform に合わせる
  • Submit 後の tracking を開始する
bb-mode submit

Submit mode に切替。Report template 生成、gate check 開始

bb-submit-gate

8 gates: scope/dup/aislop/severity/poc/format/disclosure/final

bb-cvss compute

CVSS スコア計算（暗算禁止、必ずツール使用）

bb-aislop-gate scan

25+ weakness pattern scan。HOLD = submit 不可

Session Management

bb-engage

Command用途
bb-engage initSession 開始。Target lock-in、Phase 0 完了を前提
bb-engage budgetIteration budget 確認/設定。HE Tactical loop の時間管理
bb-engage --endSession 終了。Metrics log 出力、state 保存

Iteration Budget Concept

  • 1 session = 時間制限付き。Budget を超えたら強制終了
  • Max 2 pivots per session。3回目は session 終了
  • BB_METRICS_LOG=1 で時間・アクション数を記録
  • Budget 超過 = 一旦 step back して human judgment

State Files

中間成果物の保存場所: notes/.../bb-findings/{program}/state/

  • _submission_log.md — 提出・triage status の tracking
  • state/_*.py — PoC script（heredoc 禁止、必ずファイル化）
  • state/_audit_*.py — Audit script の再実行用保存
  • findings.md — 発見事項のサマリー
  • dup-zones.md — 既知 dup zone の記録

File Rule

  • Bash heredoc + python3 -c は壊れるので禁止。必ず state/_*.py に保存して実行
  • 中間ファイルは session 終了後も残す（再開時に使える）
  • Submit 完了後の report は reports/ に移動
