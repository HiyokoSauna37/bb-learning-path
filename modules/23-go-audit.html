Go Security Patterns

Go 言語特有のセキュリティ問題。net/http routing, filepath.Join, Race Condition, Template Injection, SSRF パターンを網羅。

Theory Case Study

net/http Routing Issues

Trailing Slash の罠

// Go 1.22 以前の ServeMux
http.HandleFunc("/admin", adminHandler)
// /admin → match
// /admin/ → match (trailing slash redirect)
// /admin/../../etc/passwd → depends on implementation

// 問題: "/admin" と "/admin/" は別 pattern
// auth middleware が片方にしか適用されていない場合に bypass

path.Clean Bypass

import "path"

// path.Clean は URL path を正規化するが...
clean := path.Clean(userInput)
// path.Clean("/../admin") → "/admin"
// path.Clean("/./admin") → "/admin"

// 問題: router の pattern match と Clean の順序
// router が先に match → Clean される前に routing 決定 → bypass

Go 1.22+ の新 ServeMux

// Go 1.22 で method-based routing が追加
mux.HandleFunc("GET /api/users/{id}", getUser)
mux.HandleFunc("POST /api/users", createUser)

// 注意: {id} の wildcard が "../" を含む場合の処理
// 注意: method ベースの middleware 適用漏れ

filepath.Join on User Input

Go の filepath.Join は .. を解決するが、absolute path に対する挙動が Python の os.path.join とは異なる。

import "path/filepath"

// filepath.Join は ".." を解決する
filepath.Join("/base", "../etc/passwd")
// → "/etc/passwd" (traversal!)

// filepath.Join は absolute path で上書きしない (Python と異なる)
filepath.Join("/base", "/etc/passwd")
// → "/base/etc/passwd" (安全)

// 危険パターン:
func serveFile(w http.ResponseWriter, r *http.Request) {
    filename := r.URL.Query().Get("file")
    path := filepath.Join("/app/uploads", filename)
    http.ServeFile(w, r, path)
    // filename = "../../etc/passwd" → "/etc/passwd"
}

対策確認ポイント

// 安全: filepath.Clean + prefix check
path := filepath.Join(baseDir, filename)
path = filepath.Clean(path)
if !strings.HasPrefix(path, baseDir) {
    http.Error(w, "forbidden", 403)
    return
}

grep パターン

rg -n "filepath\.Join\(.*r\.|filepath\.Join\(.*req\." --type go
rg -n "os\.Open\(.*r\.|ioutil\.ReadFile\(.*r\." --type go
rg -n "http\.ServeFile\(" --type go

Race Conditions (Goroutine Safety)

Go の goroutine は軽量だが、shared state へのconcurrent access は race condition を生む。

// TOCTOU (Time Of Check to Time Of Use)
func transferMoney(from, to *Account, amount int) {
    if from.Balance >= amount {  // CHECK
        // 別の goroutine がここで from.Balance を変更可能
        from.Balance -= amount   // USE
        to.Balance += amount
    }
}

// 問題: mutex なし / channel なしで shared state 変更
// double-spend, race condition による認証バイパス等

Detection

# Go race detector で動的検出
go test -race ./...
go run -race main.go

# 静的検出 (grep)
rg -n "go func\(" --type go  # goroutine 起動箇所
rg -n "sync\.(Mutex|RWMutex)" --type go  # 排他制御の有無
rg -n "map\[" --type go  # concurrent map access (panic する)
Race Condition の PoC

Race condition は非決定的。PoC では -race flag での検出 + concurrent request (e.g., 100 goroutine 同時) で再現性を示す。

Template Injection

html/template vs text/template

import (
    "html/template"  // auto-escaping あり
    "text/template"  // auto-escaping なし!
)

// 危険: text/template でユーザ入力をレンダリング
tmpl, _ := template.New("t").Parse(userInput)
tmpl.Execute(w, data)  // SSTI!

// html/template でも危険なケース:
// template.HTML() で明示的にエスケープを無効化
data := template.HTML(userInput)  // XSS!

text/template RCE

// Go template action で利用可能な関数に依存
// default では限定的だが、FuncMap で追加される関数に注意
tmpl := template.New("t").Funcs(template.FuncMap{
    "exec": func(cmd string) string {
        out, _ := exec.Command("sh", "-c", cmd).Output()
        return string(out)
    },
})
// {{exec "id"}} → RCE

HTTP Client SSRF

Go の http.Client はデフォルトで redirect を follow する (最大10回)。

// 危険: ユーザ指定 URL に HTTP request
resp, err := http.Get(userURL)  // redirect follow!

// Redirect で internal service にアクセス:
// userURL = "http://evil.com" → 302 → "http://169.254.169.254/..."

// 対策: CheckRedirect で redirect を制限
client := &http.Client{
    CheckRedirect: func(req *http.Request, via []*http.Request) error {
        if req.URL.Hostname() == "169.254.169.254" {
            return errors.New("blocked")
        }
        return nil
    },
}

grep パターン

rg -n "http\.(Get|Post|Do)\(.*r\." --type go
rg -n "http\.NewRequest\(.*r\." --type go
rg -n "CheckRedirect" --type go  # 対策の有無

Crypto Misuse

import (
    "math/rand"    // 予測可能! セキュリティ用途に使ってはいけない
    "crypto/rand"  // CSPRNG (安全)
)

// 危険: math/rand で token 生成
token := fmt.Sprintf("%d", rand.Int63())  // 予測可能

// 安全: crypto/rand
b := make([]byte, 32)
crypto_rand.Read(b)
token := hex.EncodeToString(b)

grep パターン

rg -n "math/rand" --type go  # security context で使われていないか
rg -n "rand\.(Int|Intn|Read)\(" --type go  # import 元を確認
rg -n "md5\.|sha1\." --type go  # 弱いハッシュ (password に使用?)

Real Cases

GitLab (Go-based services)

GitLab の多くのマイクロサービス (Workhorse, Container Registry, Pages) は Go 製。

  • Workhorse: Pre-auth file upload handling, path traversal
  • Container Registry: Auth token validation, SSRF in manifest fetch
  • Pages: Domain routing, TLS cert handling

Grafana / Loki / Pyroscope

Grafana エコシステムは Go 製 OSS の宝庫。middleware pattern が共通。

  • Auth middleware のチェーン構造が全プロダクトで類似
  • bb-middleware-audit で middleware 適用漏れを検出可能
  • Pyroscope: /api/ prefix なしの route に auth 漏れ (過去事例)

Key Takeaways

  • filepath.Join: .. を解決する → path traversal の直接的な sink
  • net/http routing: trailing slash / path.Clean の適用タイミングに注意
  • Race condition: go func() + shared state + no mutex = race。-race flag で検出
  • text/template: auto-escape なし。html/template と間違えると SSTI/XSS
  • math/rand: 予測可能。token/secret 生成で使われていたら即報告
  • Go の型安全性は多くの injection を防ぐが、string 型の操作は依然として危険
