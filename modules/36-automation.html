Automation & Custom Tools

反復的な recon を自動化し、新しい attack surface を最速で検知する。 ただし自動化の限界を理解し、manual hunting と使い分ける。

Theory Practice

Nuclei: Template-Based Scanning

基本的な使い方

# CVE テンプレートでスキャン
echo https://target.com | nuclei -t cves/

# 全カテゴリスキャン
echo https://target.com | nuclei -t cves/ -t exposures/ \
  -t misconfigurations/ -t vulnerabilities/

# ファイルからの入力
cat alive_hosts.txt | nuclei -t cves/ -severity critical,high

# 特定技術に絞る
nuclei -u https://target.com -tags wordpress,apache,nginx

Custom Template 作成

発見したパターンを nuclei template 化すると、他のターゲットでも即座に再利用できる。 

id: custom-debug-endpoint

info:
  name: Debug Endpoint Exposure
  author: your-handle
  severity: medium
  description: |
    Application debug endpoint is exposed.

http:
  - method: GET
    path:
      - "{{BaseURL}}/debug"
      - "{{BaseURL}}/_debug"
      - "{{BaseURL}}/api/debug"
    matchers-condition: and
    matchers:
      - type: status
        status:
          - 200
      - type: word
        words:
          - "debug_info"
          - "stack_trace"
        condition: or

高度な Template パターン

id: custom-api-key-leak

info:
  name: API Key in Response
  author: your-handle
  severity: high

http:
  - method: GET
    path:
      - "{{BaseURL}}/api/config"
      - "{{BaseURL}}/api/settings"
    matchers:
      - type: regex
        regex:
          - "AIza[0-9A-Za-z\\-_]{35}"  # Google API Key
          - "AKIA[0-9A-Z]{16}"          # AWS Access Key
          - "sk_live_[0-9a-zA-Z]{24}"   # Stripe Secret
    extractors:
      - type: regex
        regex:
          - "AIza[0-9A-Za-z\\-_]{35}"
          - "AKIA[0-9A-Z]{16}"

Notification Pipeline

新しい subdomain や脆弱性を検出したら即座に通知を受け取る。 競合他社より早く report するための生命線。 

# 完全な自動化パイプライン
#!/bin/bash
DOMAIN="target.com"
DATE=$(date +%Y%m%d)
PREV="subs_${DOMAIN}_prev.txt"
CURR="subs_${DOMAIN}_${DATE}.txt"

# Step 1: Subdomain enumeration
subfinder -d $DOMAIN -silent | sort -u > $CURR

# Step 2: 差分検出
if [ -f "$PREV" ]; then
    comm -13 $PREV $CURR > new_subs.txt
    NEW_COUNT=$(wc -l < new_subs.txt)
    if [ $NEW_COUNT -gt 0 ]; then
        echo "[+] $NEW_COUNT new subdomains found"

        # Step 3: Alive check
        cat new_subs.txt | httpx -silent > new_alive.txt

        # Step 4: Vulnerability scan
        cat new_alive.txt | nuclei -t cves/ -t exposures/ \
          -severity critical,high -silent > findings.txt

        # Step 5: Notify
        cat findings.txt | notify -provider slack -id bb-alerts
    fi
fi

cp $CURR $PREV

notify 設定

# $HOME/.config/notify/provider-config.yaml
slack:
  - id: bb-alerts
    slack_webhook_url: "https://hooks.slack.com/services/xxx/yyy/zzz"

discord:
  - id: bb-discord
    discord_webhook_url: "https://discord.com/api/webhooks/xxx/yyy"

telegram:

    telegram_api_key: "BOT_TOKEN"

Custom Scripts

汎用ツールでは検出できない、ターゲット固有の脆弱性パターンは Python スクリプトで個別に検証する。

IDOR 自動チェック

import requests

BASE = "https://target.com/api/v1"
MY_TOKEN = "Bearer eyJ..."
VICTIM_IDS = ["user_123", "user_456", "user_789"]

for uid in VICTIM_IDS:
    endpoints = [
        f"/users/{uid}/profile",
        f"/users/{uid}/documents",
        f"/users/{uid}/settings",
    ]
    for ep in endpoints:
        r = requests.get(BASE + ep, headers={"Authorization": MY_TOKEN})
        if r.status_code == 200:
            print(f"[IDOR] {ep} -> {r.status_code} ({len(r.text)} bytes)")
        else:
            print(f"[OK]   {ep} -> {r.status_code}")

Rate Limit テスト

import requests
import time
from concurrent.futures import ThreadPoolExecutor

URL = "https://target.com/api/login"
PAYLOAD = {"email": "test@test.com", "password": "wrong"}

def send_request(i):
    r = requests.post(URL, json=PAYLOAD)
    return (i, r.status_code, r.headers.get("X-RateLimit-Remaining"))

with ThreadPoolExecutor(max_workers=50) as executor:
    results = list(executor.map(send_request, range(200)))

for i, status, remaining in results:
    if status != 429:
        print(f"Request {i}: {status} (remaining: {remaining})")

CI/CD Integration for Continuous Recon

# GitHub Actions example (.github/workflows/recon.yml)
name: Daily Recon
on:
  schedule:
    - cron: '0 6 * * *'  # 毎日 6:00 UTC

jobs:
  recon:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install tools
        run: |
          go install github.com/projectdiscovery/subfinder/v2/cmd/subfinder@latest
          go install github.com/projectdiscovery/httpx/cmd/httpx@latest
          go install github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest
      - name: Run recon
        run: |
          subfinder -dL domains.txt -silent | sort -u > current.txt
          comm -13 previous.txt current.txt > new.txt
          cat new.txt | httpx -silent | nuclei -t cves/ -severity high,critical
      - name: Update baseline
        run: cp current.txt previous.txt
      - name: Commit results
        run: |
          git add .
          git commit -m "recon: $(date +%Y-%m-%d)" || true
          git push

Automate vs Manual: 判断基準

自動化すべきもの

  • Subdomain enumeration (定期実行、差分検知)
  • Known CVE スキャン (nuclei templates)
  • 新規アセットの通知
  • Port scanning + service detection
  • Secret exposure チェック (定型パターン)

手動であるべきもの

  • Business logic の理解と悪用
  • Authorization bypass の creative な手法
  • Chain attack (複数の低severity を組み合わせて高impact)
  • Race condition のタイミング調整
  • 新しい attack vector の発見
原則: Automate the boring, hunt the interesting

自動化は「既知パターンの大量適用」に使う。 「未知の脆弱性の発見」は人間の創造性が必要。 自動化で attack surface を広げ、manual hunting で深く掘る。

Key Takeaways

  • Nuclei template は資産 — 一度書けば全ターゲットに再利用可能
  • 差分検知が鍵 — 新規 subdomain/endpoint を最速で把握する
  • 通知は即座に — 競合より先に report するには自動通知が必須
  • Custom script は特化型 — 汎用ツールで検出できないロジック bug に対応
  • 自動化の限界を知る — creative な hunting は人間にしかできない
