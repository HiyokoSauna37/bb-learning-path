Hunter's Mindset

BB を持続可能な practice として継続するためのメンタルモデル。 Motivation management、session discipline、long-term strategy。

Theory

Why Bug Bounty

BB を続ける理由を明確にしておく。モチベーションが落ちた時に立ち戻る場所。

Skill Building

Real-world の攻撃手法を学ぶ最速の方法。CTF より実践的

Income

副収入源。SOC analyst の知識が直接活きる

Community

世界中の hunter との交流。知識共有の文化

Resume

CVE/Advisory = 客観的な実績。転職・昇進に有利

Session Discipline

Session Budget Rule

  • Max 2 pivots per session — 3回目の pivot が必要になったら session 終了
  • Session 終了 = human step (account creation, environment setup 等) を挟む
  • 無限に rabbit hole に入るのを防ぐ仕組み

5-Minute Rule (Anti-Bot Wall)

状況判断
403 + large bodyAnti-bot wall。5分以内に pivot 判定
Rate limitedWait or pivot。自動化では突破不可
OAuth account 作成失敗Vendor server side issue。即諦め
PoC 環境構築に30分超Cost-benefit 再評価。Bootstrap helper がなければ pivot

Pivot vs Persist

Persist (続ける)Pivot (切り替える)
仮説が明確で検証手段がある仮説が曖昧で次の手がない
PoC が部分的に動いている基本的な recon すら通らない
Prior advisory で variant が期待できるProgram が anti-bot で完全ブロック
1-2 step で検証完了する検証に3+ step 必要で各 step が不確実

失敗から学ぶ

BB の failure mode (withdrawal, dup, N/A) は全て学習機会。

Withdrawal (撤回)

  • AI Slop pattern を1つ発見した = 次回は同じ mistake を避けられる
  • 撤回理由を _submission_log.md に記録する
  • mei-bb の 6件撤回は 25+ の aislop-gate pattern に結実した

Duplicate

  • Dup = 自分の finding が valid だった証明。Timing が遅かっただけ
  • Signal には影響しない（excluded from calculation）
  • Dup zone として記録し、次回は同じ area を避ける

N/A (Not Applicable)

  • N/A = submit 判断の質を上げる signal。Signal -5 のダメージは大きい
  • 「なぜ N/A だったか」を分析し、submit gate を強化する
  • 1件の N/A から得られる教訓 > 5件の dup から得られる教訓

Competition Mindset

  • Racing yourself, not others. 他の hunter と competition しても意味がない。昨日の自分より 1 step 進む
  • Top hunter の disclosed report を読んで「なぜ自分は見つけられなかったか」を分析
  • 自分の得意分野を持つ（全方位は non-sustainable）
  • 「量」ではなく「深さ」で差別化する

持続可能な Practice

Weekly Minimum

  • 1 session/week (2-3時間) を minimum として維持
  • Daily: news digest (bb-news-digest) で最新 advisory をチェック (5分)
  • Weekly: 1 target に対して Phase 0-1 を実施
  • Monthly: submission log の振り返り、tooling の改善

Burnout Prevention

  • Bounty = 0 の月があっても OK。Signal 蓄積期間と割り切る
  • 本業 (SOC) に支障が出たら BB は一時停止
  • 「見つからない日」が続いても焦らない。全ての session が training
  • Small wins を記録する（新しい pattern を学んだ、tool を改善した等）

Karpathy 4 Principles

BB adapted version of Karpathy's research principles

1. Verify Before Claiming

仮説を claim する前に必ず検証する。「コードに脆弱に見えるパターンがある」は claim ではない。「実機で exploit を再現した」が claim。

2. Boring First

派手な attack chain より、boring だが確実な finding を優先。IDOR, auth bypass, info disclosure は地味だが bounty が出る。Novel な手法は signal が安定してから。

3. Surgical Hypothesis

広範囲な fuzzing より、surgical な仮説を立てて検証。「この endpoint の この parameter は型チェックが甘い」レベルの具体性で攻める。

4. Submit-Gateable Evidence

Submit gate を通過できる水準の evidence だけを集める。「多分 vulnerable」の段階で submit しない。bb-submit-gate の 8 gates を全て PASS する evidence を用意する。

Long-term Strategy

3-Phase Career Path

  1. Signal 蓄積期 (現在)
    • huntr/GHSA で OSS source code audit のスキルを磨く
    • Low-competition program で確実な finding を submit
    • Signal > 1.0 を達成・維持
    • bb-toolkit の習熟
  2. Private Invite 期
    • Signal > 1.0 + activity で private invite を獲得
    • Competition が低い private program で bounty 率を上げる
    • 得意分野（auth bypass, IDOR, logic flaw）を確立
  3. 安定 Bounty 期
    • Private program で安定的に bounty を獲得
    • 年間 20万円超を達成 → 確定申告
    • Community での reputation 構築
    • Disclosed report で portfolio を充実

2026 Strategy (mei-bb)

  • Signal accumulation — 品質重視で positive signal を積む
  • Logic chain pivot — Pattern-based (XSS/SQLi) から logic flaw に移行
  • Verifiable sink demo — 全ての submit に E2E PoC を付ける
