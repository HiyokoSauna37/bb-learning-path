JavaScript Analysis

フロントエンドの JS ファイルには API endpoint、secret、内部ロジックが埋もれている。 これを体系的に抽出する技術。

Theory Practice

なぜ JavaScript を分析するのか

モダンな SPA (Single Page Application) ではビジネスロジックの大部分がフロントエンドに存在する。 API endpoint のパス、認証トークンの扱い方、管理者向け機能のルーティングが JS バンドル内に平文で含まれている。これは攻撃者にとって設計図を無料で入手するようなもの。

JS ファイルの収集

# getJS - ページから JS ファイル URL を抽出
echo https://target.com | getJS --complete

# waybackurls から .js ファイルを抽出
echo target.com | waybackurls | grep -E "\.js(\?|$)" | sort -u > js_files.txt

# httpx で alive check
cat js_files.txt | httpx -silent -mc 200 > alive_js.txt

# ページソースから直接抽出
curl -s https://target.com | grep -oP 'src="[^"]*\.js[^"]*"' | \
  sed 's/src="//;s/"//' | sort -u

# Burp Suite の Sitemap から Export (大量の JS を効率的に収集)
Tips: Wayback の JS は宝の山

過去のバージョンの JS には、後から削除された endpoint や 一時的に公開されていた API key が含まれている可能性がある。 現在のバージョンと diff を取ると特に有用。

API Endpoint Extraction

LinkFinder

JS ファイルから URL パターンを正規表現で抽出する定番ツール。

# 単一ファイル
python3 linkfinder.py -i https://target.com/static/app.js -o cli

# ドメイン全体
python3 linkfinder.py -i https://target.com -d -o results.html

JSLuice

Go 製の高速 JS 解析ツール。URL、secret、DOM sink を一括検出。

# URL 抽出
cat alive_js.txt | jsluice urls

# Secret 検出
cat alive_js.txt | jsluice secrets

手動での grep パターン

# API path の抽出
grep -ohE '"/api/[a-zA-Z0-9_/]+"' bundle.js | sort -u
grep -ohE "'/api/[a-zA-Z0-9_/]+'" bundle.js | sort -u

# fetch/axios の呼び出し
grep -oE 'fetch\("[^"]+"\)' bundle.js
grep -oE 'axios\.(get|post|put|delete)\("[^"]+"\)' bundle.js

# GraphQL endpoint
grep -i "graphql\|/gql\|query.*{" bundle.js

Secret Detection in JS

開発者が意図せず JS にハードコードしてしまう機密情報は想像以上に多い。

SecretFinder

python3 SecretFinder.py -i https://target.com/app.js -o cli

検出パターン例

# API Keys
grep -oE '[A-Za-z0-9_]{20,}' bundle.js  # 長いランダム文字列

# AWS
grep -oE 'AKIA[0-9A-Z]{16}' bundle.js

# Google Maps API Key
grep -oE 'AIza[0-9A-Za-z\-_]{35}' bundle.js

# Firebase
grep -oE 'firebase[a-zA-Z]*\.googleapis\.com' bundle.js

# 内部URL
grep -oE 'https?://[a-z0-9\-]+\.internal\.[a-z]+' bundle.js

# JWT (ハードコードされたテストトークン)
grep -oE 'eyJ[a-zA-Z0-9_-]+\.eyJ[a-zA-Z0-9_-]+\.[a-zA-Z0-9_-]+' bundle.js
重要: Secret の有効性確認

見つけた key/token は実際に有効かどうか確認する必要がある。 無効な key を report しても reject される。 KeyHacks を使って各サービスの key validation 方法を確認すること。

Source Maps (.map Files)

Source map はミニファイされた JS を元のソースコードにマッピングするファイル。 本番環境に公開されたままの場合、完全なソースコードが取得できる。 

# .map ファイルの存在確認
curl -s https://target.com/static/app.js | grep "sourceMappingURL"
# //# sourceMappingURL=app.js.map

# Source map のダウンロード
curl -o app.js.map https://target.com/static/app.js.map

# unwebpack-sourcemap で元のソースツリーを復元
npx unwebpack-sourcemap app.js.map output_dir/

# sourcemapper (Go tool)
sourcemapper -url https://target.com/static/app.js.map -output ./source/

Source map から得られる情報

  • 元のディレクトリ構造とファイル名
  • コメント付きの読みやすいソースコード
  • 環境変数の参照パターン
  • 内部 API のエラーハンドリングロジック
  • 認証・認可のクライアント側実装

Webpack Chunk Analysis

Webpack で build された SPA は複数の chunk に分割される。 管理者画面など、通常ユーザーには表示されない chunk にも直接アクセスできる場合がある。 

# Chunk ファイルの列挙
# webpack の runtime から chunk 名を抽出
grep -oE '[0-9]+:"[a-f0-9]+"' runtime.js

# 命名パターンから推測
# /static/js/0.abc123.chunk.js
# /static/js/1.def456.chunk.js
# admin chunk: /static/js/admin.789ghi.chunk.js

# 各 chunk の内容を確認
for i in $(seq 0 50); do
  curl -s "https://target.com/static/js/${i}.*.chunk.js" | \
    grep -l "admin\|internal\|secret" 2>/dev/null
done

DOM XSS: Source/Sink Analysis

DOM-based XSS はサーバーを経由せず、JS 内で source (入力) が sink (危険な出力) に 到達することで発生する。

Sources (攻撃者が制御可能な入力)

location.hash
location.search
location.href
document.referrer
document.cookie
window.name
postMessage data

Sinks (危険な出力先)

document.write()
innerHTML
outerHTML
eval()
setTimeout(string)
setInterval(string)
Function(string)
location.href = ...
location.assign()
jQuery.html()
$.html()

検出手順

# DOM XSS source/sink を grep
grep -nE "(location\.(hash|search|href)|document\.referrer)" bundle.js
grep -nE "(innerHTML|document\.write|eval\(|\.html\()" bundle.js

# DOM Invader (Burp Suite extension) で自動検出
# Chrome DevTools で breakpoint を設定して data flow を追跡

RetireJS: Known Vulnerable Libraries

使用されている JS ライブラリに既知の脆弱性がないか確認する。 古い jQuery, Angular, lodash などは CVE が多い。 

# CLI
retire --js --path ./downloaded_js/

# Burp Extension: Retire.js
# ブラウジング中に自動検出

# npm audit (package.json がある場合)
npm audit

Key Takeaways

  • JS = 設計図 — API path, 認証ロジック, admin 機能が全て読める
  • Source map は致命的 — 本番に .map が残っていたら全ソース復元可能
  • Secret は validate する — 見つけた key が live でなければ report 価値なし
  • Wayback の JS diff — 過去と現在の差分から削除された機能を発見
  • DOM XSS は source→sink — data flow を追跡して exploit 可能性を判断
